02Critical

C1 · predicate-prisma

Nested empty-array identities invert denials into admissions

renderNode emits Prisma's "vacuous identities": True → {AND:[]}, False → {OR:[]} (index.ts:132-133), null-Gte/Lt → {OR:[]} (:158), empty MemberOf → {OR:[]} (:179) — with no constant-folding when nested (And arm :201-202). Per open Prisma issues #17367 / #21856, nested empty arrays are silently dropped and {NOT:{AND:[]}} returns all rows. So allOf([hasResourceAttribute("role", inArray([])), tenantEq]) — "deny role-less users" — compiles to a query that admits them. The agreement tests can't catch it: the interpreter uses the same JS .every/.some semantics the compiler wrongly assumes; BEH-QD-239/242 encode the same wrong belief.
Fix  Constant-fold False (and True under Negate) inside renderNode; test against an interpreter that models Prisma's actual engine semantics.

03High

H1 · core

Fail-open: hasAttribute + resource-referencing neq allows with no resource

Evaluate.ts's HasAttribute arm guards referencesAction but never referencesResource (defined Matcher.ts:284, consumed only by the translator at Predicate.ts:292). With options.resource unset, neq(resource("tenantId")) is undefined !== x → true → allow. The exact INV-QD-032 shape guard's doc says was closed — reopened via enforce/check/assert, which don't bind a resource.
Fix  Fail with MissingResource when referencesResource(matcher) and no resource is supplied.
H2 · core

Neq on an unresolvable ref matches — contradicting BEH-QD-026

Matcher.ts:316: value !== resolveRef(...) is true whenever the ref resolves to undefined — hasResourceAttribute("raisedBy", neq(subjectId())) grants on records missing the field. The spec states "a reference that resolves to nothing denies". No test pins Neq on absent data; the repo's own SoD policy composes not(eq(...)) instead.
Fix  One semantics decision closes H1+H2: scope the spec sentence to affirmative comparators or make Neq deny on absent operands — then pin with a test.
H3 · core sinks

Decision-sink feed drops the newest records when full

DecisionSinkFeed.ts:78 uses PubSub.publishUnsafe ("Sliding means it always accepts"). In Effect v4 the sliding evict-oldest strategy runs only in the effectful publish; publishUnsafe returns-false-on-full. Once a subscriber lags and the buffer fills, every subsequent record is silently discarded newest-first — inverting BEH-QD-201. The eviction test exercises the zero-subscriber replay path, so the suite and mutation gate both miss it.
Fix  Effect.asVoid(PubSub.publish(pubsub, record)) (never suspends on sliding) + a subscriber-active overflow test.
H4 · audit

Interrupted half-open probe write permanently bricks the circuit breaker

Half-open allows one probe (claimProbe one-shot, CircuitBreaker.ts:204-207); the status read (:146) never recovers a HalfOpen with openedAt: undefined. The probe write runs under Effect.result (AuditDecisionSinkLive.ts:149) — an interruption or defecting store adapter releases nothing. The breaker then treats every future record as open: staged rows never commit (unbounded staging growth) or entries drop, silently — exactly while the backend is flaky.
Fix  Release the probe on abnormal exit (Effect.onExit) and/or age out a stuck HalfOpen; test interrupting a half-open probe.
H5 · react

settled() can suspend a remounted tree forever

settled.ts:73-77 keys pending/resolvers/subscribed by atom only, not by registry. A QadiProvider remount builds a fresh registry but inherits the dead promise (returned before any freshness check) → permanent suspension; two concurrent providers share one listener, so the second registry's transitions never resolve.
Fix  Key by (registry, atom), or validate the memo against the current registry before reuse.
H6 · core codec

Unbounded decode of untrusted sink records

Policy.fromJson guards with exceedsJsonDepth (512) precisely because Schema's recursive descent RangeErrors — but decodeRecordWire (SinkCodec.ts:463, self-recursive TraceSchema + embedded Policy) has no guard, and its consumers are untrusted: devtools decodes SSE frames (Source.ts:206), where the RangeError surfaces as a defect that freezes the live timeline.
Fix  Extract the depth guard, run it in decodeRecord/Hydration, fail typed so malformed drops the frame.
H7 · predicates

Gte/Lt with string values compile to live dialect comparisons

Reference evaluatePredicate requires both sides number (constant-false otherwise), but both compilers admit any isSafeValue and render "title" >= $1 / {level:{gte:"3"}}. MySQL/SQLite coerce and admit rows the reference denies; Prisma string-compares. Same INV-QD-047/048 disagreement class as the handled Date/NULL cases — on the parameter side.
Fix  Constant-fold non-numeric Gte/Lt exactly like the null arm already does.
