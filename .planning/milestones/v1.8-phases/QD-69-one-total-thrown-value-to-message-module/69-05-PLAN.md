Design recorded (owner: choose the most complete and clean design and record why):
- react (D-16): a private `namedLine(error)` reads, inside one `try`, an `Error`'s `message` once into an `unknown`
  `const`, and when that is a string returns `${thrownMessage(error.name)}: ${message}` (the name rendered through
  `thrownMessage`, so a non-string name reads as its `String` form, as the old template did, and a symbol name cannot
  throw); otherwise, or when a getter throws, it returns `undefined`, and `errorLine` is
  `namedLine(error) ?? thrownMessage(error)`. A non-string message therefore never prints the name twice: an `Error`
  whose `message` is 42 reads `Error: 42` through its standard string form (P2), and one with its own `toString` reads
  that (S3). Each condition has a case that only it decides: P1 (an object that is not an `Error` but has a string
  `message`) kills an `instanceof` mutant, S3 kills a `typeof` mutant, and the `TypeError: host boom` pins kill the
  rest.
- devtools (D-15): "reads `cause` first" stays (D-06), and the whole rule is one expression,
  `thrownMessage(fieldOf(error, "cause") ?? fieldOf(error, "reason") ?? error)`, where `fieldOf(error, key)` with
  `key: "cause" | "reason"` returns `Reflect.get(Object(error), key)` inside a `try` whose empty `catch` falls through to
  `undefined`. No `as`, no `_tag`. D-15's third step, the error's own string `message`, is `thrownMessage(error)`'s first
  read: every failure the capture sees is a port's typed error, an `Error` subclass, so a separate `message` read would
  be a branch no port error can tell apart from `thrownMessage`'s, a mutant no test could kill. A `CustomPredicateError`
  (an own `reason`, no own `message`, a `name` holding the predicate's name) is captured with its reason and replays
  with it (C2); a port error with no cause, reason or message of its own records the empty string (C3), because a
  replay rebuilds the error class from the port and its tag's text would replay as noise. A `null` cause now reads as no
  cause, where it read `null`. This is a visible change, named in the CCR row and the devtools changeset (69-07).

Shell and commit rules: as in 69-01's objective. No comment may hold the inline Error-or-String ternary or the old
angle-bracketed placeholder: the negative gates count comment lines.
