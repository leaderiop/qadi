guarded one.

Design recorded (owner: choose the most complete and clean design and record why):
- Each site passes the same cause it passed to `Cause.pretty` to `causeMessage`, so a cause that renders keeps its
  exact text and every existing pin of a rendered reason stays green unchanged.
- `GatesFeed`'s `stated` keeps its two outputs and its caller's fallback. Its reason is `causeMessage(Cause.die(thrown))`
  (the same `Cause.pretty` text for a throw that renders); its hand-written guard around `Cause.pretty` goes, because
  that guard is the rule `causeMessage` already holds (D-14: one rule, one place). Its key is unchanged: the error's
  `name: message`, else the reason, read inside a `try` whose `catch` returns the caller's fallback, so two throws are
  still compared as before and two throws that cannot be read still compare equal. The fallback constants are kept as
  keys only; what the panel shows for a throw that cannot be rendered is now the one placeholder, as everywhere else,
  so the four pins of that throw move to it in the task that changes the wording.
- The `DiagnosticsStatus` overview row changes in the task that changes the diagnostics feed, so the overview never
  describes code the tree does not hold.

Shell and commit rules: as in 69-01's objective. No comment may hold `Cause.pretty` followed by an opening
parenthesis: the gate below counts comment lines.
