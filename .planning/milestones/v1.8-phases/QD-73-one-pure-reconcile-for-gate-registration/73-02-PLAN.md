## ADR-QD-186's content

File `spec/decisions/186-gate-registration-is-one-keyed-reconcile.md`, title
`# ADR-QD-186 — Gate registration is one keyed reconcile`. Document Control: Document ID `QADI-ADR-186`, Revision
`1.0`, Effective Date `2026-11-22`, Status `Accepted — extends ADR-QD-140 and ADR-QD-111`, Author, Classification,
Change History `1.0 (2026-11-22): new — gate registration is one keyed reconcile (ARCH-120, CCR-QD-465)`.

- `## Context`: in the code before ADR-QD-186, registration was split across three places holding one rule each:
  `reconcile` registered and unregistered from two index-aligned arrays (`wanted`, `current`) and did no update; the
  hook kept four refs and three effects, one of them a hand-written state diff keyed on the joined states; `useGates`
  passed two `Record.values` results and relied on their key order agreeing; and the registry's handle had its own
  equal-state check, the third place that rule was written.
- `## Decision`, numbered:
  1. The wanted set is a `ReadonlyMap<string, GateWanted>` keyed by gate id; `GateWanted` is `{ identity, state }`.
     `GateIdentity` has no `id`: the key is the id, so a key and an id cannot disagree and two entries cannot share an
     id.
  2. One step: for each live id, when `wanted` holds it with the same identity, the entry is kept (the same
     `Registered` object) and its handle is told the wanted state; otherwise it unregisters. Then each wanted id not
     kept registers with its identity's `kind`, `policy` and `resource`, the wanted `state`, and the marker's element
     for a wrapping identity. Unregistering runs before registering, so a changed identity re-registers under its own
     id without colliding with itself. It returns a new `Map` and never mutates `live`.
  3. `sameIdentity` compares exactly `kind`, `atom`, `wraps` and `marker`; a changed `policy` or `resource` alone does
     not re-register (the atom changes with the question, so a different question is a different atom).
  4. The equal-state rule is written once, in `GateHandle.update` (`buildGateRegistry`): `reconcile` tells every kept
     handle its state and compares nothing; `Registered` holds no copy of the state; the hook holds no state diff.
  5. Pure, as ADR-QD-140 made it mean: `GateWriter.ts` imports nothing from React; `reconcile` is deterministic in its
     arguments, acts only through the writer and handles it is handed, and returns a fresh map.
  6. The failure rule: if a step throws, the steps after it do not run; every registration this call made is
     unregistered, each in turn, a throwing one not stopping the rest; then `reconcile` throws by ADR-QD-177's count
     rule: one value is thrown as it is, more than one as one `AggregateError` holding them in the order thrown.
     Then, in these words verbatim (the same words `reconcile`'s doc comment and BEH-QD-702 carry): "`reconcile`
     never mutates `live`: if a step throws after an earlier step unregistered an entry, `live` still holds that
     entry, its handle already unregistered, and unregistering that handle again is a no-op." A handle from
     `buildGateRegistry` never throws, so with the package's registry nothing stays registered that the caller's map
     does not hold, and the caller's teardown, unregistering every handle its map holds, ends with nothing registered.
  7. `useGateRegistrations(writer, wanted)` keeps one ref, `registered`, and one registration effect with no
     dependency list, which calls `reconcile` with the committed render's own `wanted`; beside it stays the teardown
     keyed on `writer`, declared first, whose cleanup unregisters every registration when the hook unmounts or its
     writer changes. "One effect" means one registration effect: an effect's cleanup is React's only unmount signal
     and also runs before every re-run, so one effect would either re-register on every commit or leak on unmount.
     When `writer` is `undefined` the effect returns at once.
  8. `useGates` makes one keyed pass over the questions (`Record.map`) that yields, for each name, its `GateRead` and
     its `GateWanted`, built from the same values; `wanted` is built from that pass as `new Map(…)` of id and wanted
     pairs, keyed by the entry's own id (`base`, or `` `${base}/${name}` `` for a grouped hook). No callback fills a
     collection by a side effect, and nothing depends on two collections agreeing on key order.
- `## What enforces it`: the compiler — `wanted` is a `ReadonlyMap` (an array is refused), `GateIdentity` has no `id`,
  `GateCurrent` does not exist, `Registered` has only `identity` and `handle` (pinned in
  `GateWriter.reconcile.tst.ts`). Tests only — the step's rules, its call order, the failure rule,
  a second unregister of an entry left in `live` included (`GateWriter.reconcile.test.ts`; the registry's own
  "unregister is idempotent" in `GateRegistry.store.test.ts`), the equal-state no-op (`GateRegistry.store.test.ts`, `GateWriter.test.tsx`), and
  behaviour preserved (`GateRegistration.characterisation.test.tsx`). Neither enforces that no other module diffs
  states; review and the BEH do.
- `## Alternatives considered`: keeping `identity.id` beside the key; a `Record<string, …>` wanted set; an array of
  `GateWanted`; comparing state in `reconcile` against a copy kept in `Registered`; a plan/apply split returning a
  closed union of steps; folding the teardown into the registration effect; a best-effort step that keeps going after
  a throw. Each with the reason from CONTEXT (two statements of one fact; key coercion and no order; order kept by the
  caller; a second copy of the registry's field; needs the state copy and the writer anyway; re-registers every commit
  or leaks; a half-applied step whose throw is lost).
- `## Consequences`: AGENTS.md §13 unaffected — the registry records that a guard exists and what it renders now,
  never a retained verdict; no export changes (`GateWriter.ts` and `useGate.ts` are out of the barrel), so no
  changeset; the notification count per transition is unchanged; the decision's behaviours and invariants are
  BEH-QD-701 to BEH-QD-705 and INV-QD-391, INV-QD-392, linked by the anchors in the interfaces.
- `## Related`: ADR-QD-053, ADR-QD-080, ADR-QD-103, ADR-QD-111, ADR-QD-140, ADR-QD-177, each a relative link.
