## The keyed reconcile (Task 1)

`GateWriter.ts`:
- `GateIdentity` loses `readonly id: string`; its `atom` doc reads that `sameIdentity` compares it rather than the raw
  policy and resource, so an inline policy does not churn registration.
- `sameIdentity(a, b)` is `a.kind === b.kind && a.atom === b.atom && a.wraps === b.wraps && a.marker === b.marker`;
  its doc names exactly those four and says `policy` and `resource` are left out because the atom changes with the
  question.
- New `export interface GateWanted { readonly identity: GateIdentity; readonly state: GateRenderState }`, with a
  one-line doc: one guard as the committed render wants it registered; its gate id is the key it is stored under.
- The index-aligned type is deleted.
- `reconcile(writer: GateWriter, live: ReadonlyMap<string, Registered>, wanted: ReadonlyMap<string, GateWanted>):
  Map<string, Registered>`: `next` and a local `made: Array<GateHandle>`; inside one `try`: for each `[id, entry]` of
  `live`, `want = wanted.get(id)`; when `want` is defined and `sameIdentity(want.identity, entry.identity)`,
  `next.set(id, entry)` then `entry.handle.update(want.state)`; otherwise `entry.handle.unregister()`. Then for each
  `[id, { identity, state }]` of `wanted` not in `next`: `handle = writer.register({ id, kind: identity.kind, policy:
  identity.policy, resource: identity.resource, state, element: <the element rule verbatim> })`, push it to `made`,
  `next.set(id, { identity, handle })`. In the `catch (error)`: `thrown = [error]`; for each handle in `made`, call
  `unregister()` in its own `try`, pushing what it throws; then throw `thrown[0]` when it is the only value, else
  `new AggregateError(thrown, "A gate reconcile step threw, and so did its rollback.")` (the message inline, not a
  module constant, so no static mutant appears). Return `next`.
- `reconcile`'s doc, one-line summary first ("Brings `live` in line with `wanted` in one step and returns the next
  live registrations."), then: the three outcomes and the visiting order; that it tells every kept handle its state and
  compares nothing (the handle's `update` is where equality is decided); that it acts only through the writer and the
  handles it is handed; the failure rule in ADR-QD-186's words, ending with this sentence verbatim (wrapped as the
  comment wraps, same words as ADR-QD-186 item 6 and BEH-QD-702): "`reconcile` never mutates `live`: if a step throws
  after an earlier step unregistered an entry, `live` still holds that entry, its handle already unregistered, and
  unregistering that handle again is a no-op." Then that a handle from `buildGateRegistry` never throws; and what
  neither the compiler nor its tests enforce, if anything, said plainly.
  Drop the sentence about calling only register and unregister. Cite ADR-QD-186 and keep the ARCH-76 paragraph's point
  (no React, tested without rendering) in its current words where still true.
- Header line 4 becomes "…the store that builds one (`buildGateRegistry`), and the one step that brings a guard's
  wanted registrations, keyed by gate id, in line with the live ones."

`useGate.ts`:
- Imports: `reconcile` only from `./GateWriter.ts` (no `sameIdentity`); types `GateKind`, `GateWanted`, `GateWriter`,
  `Registered` plus any still used (`GateIdentity` for the literal's annotation if kept); remove what is unused.
- `useGateRegistrations(writer: GateWriter | undefined, wanted: ReadonlyMap<string, GateWanted>): void`: the
  `registered` ref as at `phase_base`, the teardown effect verbatim, then
  `useEffect(() => { if (writer === undefined) return; registered.current = reconcile(writer, registered.current,
  wanted); });` with no dependency list. Nothing else: no other ref, no other effect.
- Its doc, one-line summary first ("Registers a guard's wanted registrations with `writer` while it is mounted."):
  `wanted` is keyed by gate id, so an id is stated once and cannot repeat; a single-question guard passes a map of
  one; the registration effect runs after every commit with that commit's own `wanted`, and an unchanged identity and
  an unchanged state make no notifying call (the handle decides equality); the teardown keyed on `writer` is declared
  first and is the one place registrations end on unmount or a writer change, because an effect's cleanup is React's
  only unmount signal and also runs before every re-run; with `writer` undefined every effect returns at once. Say
  plainly that only tests check the hook keeps no other copy of identities or states.
- `useGates`, per D-07 ("`wanted` is built from that iteration as `new Map(…)`"): replace the `entries` and
  `identities` passes with one `Record.map(questions, (question, name) => …)` whose callback computes `result`,
  `outcome` and `id` once and returns `{ entry, want }`: `entry` the `GateRead` exactly as at `phase_base` (`atom`,
  `result`, `outcome`, `id`, `ref`), `want` the `GateWanted` `{ identity: { kind, atom: atomOf[name], wraps, policy:
  question.policy, resource: question.resource, marker }, state: outcome._tag }`. Then `const entries =
  Record.map(asked, (gate) => gate.entry)` and `const wanted = new Map(Record.collect(asked, (_name, gate): readonly
  [string, GateWanted] => [gate.entry.id, gate.want]))` (the return annotation types the pair; no `as`). Nothing is
  filled by a side effect inside a callback, the id is read off the entry it belongs to, and no two collections must
  agree on order. Call `useGateRegistrations(scope.writer, wanted)`. Update the doc sentence that lists what
  `useGates` does if it names the removed pass.
