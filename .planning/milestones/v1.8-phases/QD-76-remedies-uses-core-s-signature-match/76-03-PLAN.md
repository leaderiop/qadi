names) is unchanged. Its doc comment gains one sentence: the subject id is absent exactly when the request's subject id
is not a string, which only a request the key refuses can hold, and the cause then carries `describeKeyRefusal`'s
sentence, which names it (BEH-QD-410).

**`SignatureHistory.ts`**: module-private `const isSubjectId = Schema.is(SubjectIdSchema);` and `const isResourceId =
Schema.is(ResourceIdSchema);` beside the description, and `signatureHistoryPort.failure` becomes `([query], cause) => new
SignatureHistoryUnavailable({ ...(isSubjectId(query.subjectId) ? { subjectId: query.subjectId } : {}),
...(isResourceId(query.resourceId) ? { resourceId: query.resourceId } : {}), cause })`, so building the error is total
over every request value and no call site needs a guard. Its comment says so in one sentence: each member is set only
when its schema admits the request's value, so a refused request fails as this error and never as a defect.

## The judgement and its pieces

boolean; readonly onFile: number }`, with the parameter types of `signatureMatches`, answering `{ matched:
signatureMatches(signatures, meaning, signerRole), onFile: signatures.length }`. Its doc comment: one-line summary

answer `askSignature` hands the walk and `signatureAnswerFromSignatures` returns, built here once, and that the return
