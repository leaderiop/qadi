## The dock model on the derived store

- Module scope, beside `JoinKey`: `interface MergeKey { readonly fed: DiagnosticsSnapshot; readonly supplied:
  DiagnosticsReading | undefined }` (doc: the two things the shown reading is merged from, compared by identity) and
  `function mergedOf(key: MergeKey): DiagnosticsSnapshot` (doc: the sampled snapshot with the supplied reading laid
  over it, the feed's own snapshot when the merge changes nothing), its body the inner merge function's, reading
  `key.fed` and `key.supplied`.
- In `makeDockModel`, after the diagnostics feed: `const shownReading = yield* makeDerivedStore({ parents:
  [diagnosticsFeed], key: (): MergeKey => ({ fed: diagnosticsFeed.getSnapshot(), supplied: inputs.reading }),
  compute: mergedOf })`. The two `let`s, the inner merge function, the hand trigger and its subscription go.
- After the gates feed, one comment (the join is pure over the feed's snapshot, the supplied questions and the poll's
  status, so no snapshot pairs a question from one moment with a guard from another; built after the shown reading and
  the feeds and before any host listener, so the join and the cards move first), then `const questions = yield*
  makeDerivedStore({ parents: [gatesFeed, shownReading], key: (): JoinKey => { …the existing key reader's body… },
  compute: (key) => joinQuestions(joinInputOf(key)) })`.
- Then one comment (the port cards are a function of the shown reading alone; no host code is read, so nothing here is
  guarded), then `const services = yield* makeDerivedStore({ parents: [shownReading], key: (): ServicesInput => { …the
  existing services key reader's body… }, compute: portCards })`.
- The closed flag, both standalone key readers, both last keys, both hand triggers, the three manual subscriptions and
  the finalizer go. The returned model is unchanged (`questions` and `services` stay `{ subscribe, getSnapshot }`).
- In `configure`: the comment above the gates feed's configure says the feed re-reads the registry and the thunk
  before the shown reading is refreshed, whose publish joins through them, so one `configure` reads no registry the
  host has just handed away and publishes one join; the last statement is `shownReading.refresh()` under a comment
  saying a reading that moved is a new shown reading, which the join and the cards follow through their parents.
- Imports: `{ makeDerivedStore, type ReadableStore } from "./ExternalStore.ts"`; drop any import left unused.
- Header: line 2 becomes `The dock's stores and the rules between them, as one model a test can drive without
  rendering.`; the count paragraph (`:24-35`) becomes one paragraph headed `**Its stores.**`: the stores are listed
  once, in BEH-QD-700, and a test of a built model checks that list; the shown reading, `questions` and `services` are
