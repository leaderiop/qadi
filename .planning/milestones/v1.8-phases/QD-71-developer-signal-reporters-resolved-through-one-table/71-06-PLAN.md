   - Context: every developer signal's reporter was resolved by a hand-written function, each restating the same three
     rules (a supplied reporter replaces the default and is contained, the default speaks only in development, a throw
     is named by the reporter's option), and the reporter names were a hand-kept list beside them. `makeQadiAtoms`
     built its registry through `makeGateRegistry`, passing its own `onGateIdCollision` under the registry's option, and
     the collision resolver named a throw `onGateIdCollision` whichever entry point it came through, so a direct
     `makeGateRegistry({ onIdCollision })` caller read the wrong option name (shown on the phase base by a failing
     test). AGENTS.md §13 said no module-scope state was left in `@qadi/react` while the production-instrumentation
     latch was one.
   - Decision, numbered: (1) one table, `SIGNALS` in `packages/react/src/DeveloperSignals.ts`, a record over every
     developer signal's tag, total by `satisfies SignalTable`; each row states where its console default speaks
     (`Development`, `Production`, `Everywhere`), how often (`PerEvent`; `OncePerProcess` for
     `InstrumentedInProduction` only), its default (`says`) and, per entry point, the option it is reported under and
     when it is resolved (`OncePerAtomSet`, `OncePerRegistry`, `OncePerCall`, `OnEveryReport`); (2) `ReporterName` is
     derived from the table's option names; (3) one resolver, `reporterFor(row, entry, supplied)`, contains a supplied
     reporter under the option the row names for that entry point, and otherwise gives the row's default under its
     row's condition; a throw is announced through `ReporterThrew`'s own row, which speaks in every environment;
     (4) the entry point decides the name: the registry closure is `buildGateRegistry` in the package-private
     `GateWriter.ts`, handed a reporter already resolved, so the atom set names its own option and `makeGateRegistry`
     its own, no throw is contained twice and no public type changes; (5) each hydration call site reads its own row,
     so the dehydrate default cannot be paired with the hydrate row; (6) every reporter is resolved where it was, and
     the table states when; (7) the production-instrumentation latch stays process-scoped, as the one piece of
     module-scope state in library source, counted by `MODULE_STATE_BUDGET` in `scripts/check-house-style.mjs` with
     its AGENTS.md §6 table, and AGENTS.md §13 corrected in place.
   - Alternatives considered: the latch under an atom set or a provider ref (both narrower than a process, so a page
     with two providers would print the line twice; a provider can be handed atom sets it did not build; a supplied
     reporter already gets once per mount); passing the atom set's contained reporter on to `makeGateRegistry`
     (contained twice, a throw announced twice); a new public option naming the entry point (changes a public type for
     a name the library already knows); keeping the four resolvers as projections of the table (four names for one
     rule); a `const` holding a mutable container counted by the budget (would flag `Policy.ts`'s depth memo and the
     read-only lookup tables, none of which a caller can observe; rebinding is the shared state).
   - Consequences: what the compiler refuses (a missing row, TS2741 naming it; an extra row; a second once-per-process
