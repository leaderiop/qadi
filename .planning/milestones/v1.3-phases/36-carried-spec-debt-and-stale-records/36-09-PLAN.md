## Flagged assumptions

- **A2's grant atom is keepAlive, one per question.** D-14 rejects keepAlive on the seed itself because it pins every
  seed forever; the grant atom is per question handle, holds only an opaque `SeedGrant`, and is forgotten with the
  handle when the book evicts the question (HL6), so the bound stays `maxTrackedQuestions`. HL5 pins that a question
  never hydrated leaves no node.
- **Seed assumption A1 (research).** The design relies on `getNodes().get` never creating a node and on a seeded,
  never-built keepAlive node holding its value; 36-03's two canaries pin both against the installed `effect`, and 36-14
  lists A1 for human review.
- **WX-04 (unclassified edge, flagged).** The `state.announced` guard and the `instanceof SeedGrant` narrowing are the
  plausible survivors; HL4 and the engine cases kill them. 36-14's after-run names any survivor.
- **The subject keepAlive holds one value per atom set.** The atom set is per provider tree; the subject is replaced on
  every provider render through `withEquality`, so pinning it keeps one subject, never a history.
