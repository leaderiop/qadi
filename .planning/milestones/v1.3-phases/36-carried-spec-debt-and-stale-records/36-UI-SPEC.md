# Phase 36 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Three visible changes in `@qadi/devtools`, all extending Phase 34's approved contract
(`34-UI-SPEC.md`) rather than starting a second one (CONTEXT D-02 item 4, D-13, D-16):

1. **A timeline Stopped notice** (D-13): when the timeline read dies with a defect, `TimelineStatus` is
   `Stopped { reason }` and the dock says so, on every screen that reads the timeline.
2. **A visible focus indicator** on every programmatic focus target the dock owns: the Services and
   Questions screen roots (D-02 item 4) and the one new target this phase adds, the dock body.
3. **A hardened Restart button** (D-16) in the shared stopped box, so Diagnostics and Timeline both get it.

Every colour, font and size below is an existing token from `packages/devtools/src/react/theme.ts`.
**No new design token is needed.** The one new styling value is a stroke width (the 2px ring, below), which
is a literal in the focus helper and not a token, the same way `1px` borders are literals today.

**Dock palette.** The dock is dark and not themed (`theme.ts` header: "Dark by default, and not themed"). It
paints its own `colors.surface` behind everything, so a light host page never shows through it. There is
exactly one palette, and every ratio below is computed for it. "Both themes" is answered by that fact, and a
second set of numbers does not exist.

## Spacing Scale

Declared by this phase (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| sm | 8px | Notice `marginBottom` (the `panel` default), reason block padding and top margin, button top margin; all unchanged from Phase 34 |

Inherited exceptions, reused unchanged and not introduced here:

| Value | Where it comes from | Usage here |
|-------|---------------------|------------|
| 12px | The screens' root `padding: 12` (`ServicesPanel.tsx`, `QuestionsPanel.tsx`, `Simulator.tsx`) | The timeline notice's wrapper padding (`"12px 12px 0"`) and the notice's own horizontal padding (`"8px 12px"`), so its text aligns with the screens' content |
| 2px 8px | `button(false)` in `theme.ts` | The Restart button, unchanged |

Exceptions introduced: **2px**, the focus ring's stroke width, and **-2px**, its inset offset. They are a
stroke, not a spacing value. 2px is the WCAG 2.2 SC 2.4.13 minimum thickness, which the ring adopts although
that criterion is AAA. The offset is negative so the ring draws inside the target's box (see Focus indicator).

Gap rule for the timeline notice: the wrapper has no bottom padding, and the notice keeps the `panel`
`marginBottom` of 8, so the screen content sits 8px below the notice (20px on screens whose own root carries
`padding: 12`: Inspector-with-selection, Policies, Simulator). That is accepted and not tuned per screen.

## Component 1: the timeline Stopped notice

### Which screens read the timeline (found, not assumed)

`DockModel` pushes the one shown `Timeline` into every store it owns (`spread()`: the explorer, the
simulation and the dock session). Reading the code, the screens that render from the timeline are:

| Tab | Reads the timeline through | Renders the notice |
|-----|----------------------------|--------------------|
| `log` | `DockSession` rows (`DecisionLog`) | yes |
| `inspector` | `DockSession` selection, an entry from the timeline (`Inspector`) | yes |
| `policies` | the explorer's sightings, `catalogueOf(shown, ...)` (`PolicyExplorer`) | yes |
| `simulator` | the simulation's sightings and the replayed entry (`Simulator`) | yes |
| `roles` | the catalogue's roles only (`RoleViewer`) | no |
| `services` | the diagnostics reading only (`ServicesPanel`) | no |
| `questions` | the diagnostics reading only (`QuestionsPanel`) | no |

The toolbar also reads it on every tab (the decision counts, the `live`/`paused` toggle). It is **left
unchanged**: `live`/`paused` is the reviewer's own freeze control and not a health signal, and the counts
stay true as of the entries the timeline kept. The notice explains them on the four screens where the stale
entries are the content.

The rule is encoded as data, so a tab added later cannot skip the decision: a `Record<TabId, boolean>`
(`readsTimeline`) in `DevtoolsDock.tsx`, closed over `TabId`, so a new tab is a compile error until it says
which it is. It is not a `Set`, which would let a new tab default to "no".

### Placement

One notice, rendered by `Screen` in `DevtoolsDock.tsx` as the **first sibling above the chosen screen**,
inside the scroll `body`, when `readsTimeline[tab]` is true. The notice is not rendered inside any screen
root (unlike Phase 34's, which sat inside the two roots), because four unrelated screens share it and none
of them has a common root. `Screen` returns a fragment of the notice and the screen, so tab-to-tab moves
among the four keep the notice mounted (same position, same type) and so do not re-announce it.

```
<div style={body} tabIndex={-1} data-testid="qadi-dock-body" {...focusRingProps}>     <- the focus return target
  <div data-testid="qadi-timeline-notice-slot" style={{ padding: "12px 12px 0" }}>     <- only while Stopped
    <section data-testid="qadi-timeline-notice" style={stoppedStyle}>
      <div role="alert" | none  data-testid="qadi-timeline-stopped" data-announce="alert|none">
        <strong>Timeline stopped.</strong> {body}
      </div>
      <pre data-testid="qadi-timeline-reason" role="group" aria-label="Why the timeline stopped" tabIndex=0>
      <button type="button" data-testid="qadi-timeline-restart">Restart timeline</button>
    </section>
  </div>
  ...the screen, unchanged
</div>
```

The slot and the notice are rendered **only while `Stopped`**. There is no always-present polite region:
unlike diagnostics, the timeline has no `Starting` state (`Reading` is the ordinary, quiet state), so there
is no polite announcement to pre-mount a live region for.

### Reuse of Phase 34's notice contract

There is **one** stopped-notice style and behaviour, not two. The implementation extracts the stopped box out
of `DiagnosticsNotice.tsx` into one package-private component (for example `StoppedBox`, in its own file) that
both the Diagnostics notice and the Timeline notice render. Their differences are exactly the table below,
and nothing else; the existing `qadi-diagnostics-*` test hooks and copy are unchanged, so Phase 34's tests
stay green.

| Aspect | Rule (identical to Phase 34 unless marked) |
|--------|--------------------------------------------|
| Box style | `panel` spread, `padding: "8px 12px"`, `border: 1px solid colors.error`, `background: withAlpha(colors.error, 0.12)`, text `colors.text`, lead phrase `colors.error` at weight 600 |
| Alert | `role="alert"` on the lead and body `<div>` only, the first time a given stop is shown; none after. The reason and the button are **outside** the alert |
| Once per stop | A `StopLedger` ref owned by `DockFrame` (a second one, `timelineAnnounced`, beside the diagnostics one, because the two feeds stop independently). The mode is fixed at mount with `useState(() => ledger.current.stop !== status)`; the ledger is written in a `useLayoutEffect`; the notice is **keyed per stop** so a second stop remounts and alerts again. `StopLedger` is made generic over the status type (`stop: S \| undefined`) so one definition serves both |
| Reason | `<pre>` outside the alert: `margin: "8px 0 0"`, `padding: 8`, `background: colors.surface`, `border: 1px solid colors.border`, `borderRadius: 4`, `fontFamily: "inherit"`, `fontSize: font.sizeSmall`, `whiteSpace: "pre-wrap"`, `overflowWrap: "anywhere"`, `maxHeight: 96`, `overflow: "auto"`, `tabIndex={0}`, `role="group"`. Omitted when `reason` is `""`. `Cause.pretty` output, verbatim, never reworded or truncated |
| Button | `type="button"`, visible text is the accessible name, no `aria-label`, no `aria-pressed`, no disabled or pending state. **Hardened per Component 3** |
| No timers, no animation, no auto-dismiss | as Phase 34 |
| Marked difference | Timeline has **one** body (no `sampled` variant): a timeline has no "before the first reading" state, its entries are already on screen |

### Restart: yes, and what it restarts

**The notice has a restart action: "Restart timeline". It re-reads the same source from the start.** This is
the same way out Diagnostics gives, and it avoids a dead-end notice. The alternative the research weighed
(recovery only by passing a new `source` or `capacity`) was rejected here because a reviewer in the dock has
no control over the host's props, and the notice would say "stopped" with no action in reach.

What it does, precisely:

- It forks a fresh read of the **current** `source` in the feed's own scope, interrupting nothing (the dead
  fiber has already ended), and sets the status to `Reading` at once.
- **The entries already shown are kept.** A re-read replays the source's backlog, and the timeline dedupes on
  `(environment, id, at)` (`Timeline.ts`, `ingest`), so nothing is shown twice. After a `clear view`, a
  restart brings the backlog back, which is the expected meaning of "read it again".
- If the source dies again, that is a new `Stopped` value: the notice remounts and alerts again, and the
  reason names the cause. Restart is idempotent and has no confirmation, since it discards nothing.
- A new `source` or `capacity` prop also returns the status to `Reading` (the existing feed behaviour, TF11
  and TF14); Restart is the reviewer's in-dock equivalent.

**This adds one member to D-13's model surface** that the research did not list: the timeline status readout
carries a `restart` (`{ subscribe, getSnapshot, restart }`, the shape of `DiagnosticsReadout`). That makes
the timeline feed gain a `restart` command, `DockModel.timelineStatus` expose it, and BEH-QD-465's restated
text name it. It is flagged for the planner as a decision that this UI-SPEC adds to D-13.

### Interaction

1. Click, Enter or Space on the button calls the feed's `restart()`. The status goes to `Reading`, so the
   whole notice unmounts on the same render.
2. **Focus return.** The button unmounts on restart, which would drop focus to `<body>`. The click handler
   calls `restart()` and then focuses the dock body: `event.currentTarget.closest("[data-testid='qadi-dock-body']")`
   narrowed with `instanceof HTMLElement`, then `.focus()`. (The Diagnostics notice keeps focusing its screen
   root with `closest("[data-diagnostics-status]")`; the shared box takes the target selector as a prop, so
   there is still one handler.) The body is the stable region that holds the screen and the notice, it never
   unmounts while the dock does, and it carries the focus indicator below, so a keyboard user sees where
   focus went. It is `tabIndex={-1}`: a programmatic target, not a tab stop.
3. **Announcement of success.** A successful restart is not announced. `Reading` is the ordinary state and the
   dock adds no polite region for it, and no timer-based "restarted" message (Phase 34 forbids timers). The
   outcomes a screen-reader user needs are announced where they occur: a stop alerts (once per stop) and a
   stop that follows a restart alerts again. This is a stated, accepted gap, not an oversight.
4. A stop that happens while the reviewer is on `roles`, `services` or `questions` has never been announced;
   the first visit to one of the four timeline tabs presents it as `role="alert"`, the correct first
   announcement (the ledger records only stops a notice has delivered, as in Phase 34).
5. Hidden `<Activity>` and rebuild: the model is rebuilt at `Reading`, so a stop does not survive a rebuild,
   and the ledger lives in the rebuilt tree, so a stop after a rebuild alerts afresh (as Phase 34 stated).
6. Both notices can be shown at once on no screen: the timeline notice appears only on the four timeline
   tabs and the diagnostics notice only on Services and Questions, so they never stack.

### Copy (this notice)

Plain, specific, sentence case, no exclamation, no emoji. The panels' voice states a fact and what it means.

| Element | Copy |
|---------|------|
| Lead phrase | Timeline stopped. |
| Body | The source failed with an unexpected error and is no longer delivering decisions. What it delivered before it stopped is kept, and nothing new will arrive. |
| Reason (accessible name) | Why the timeline stopped |
| Primary CTA | Restart timeline |
| Error state (reason) | The `Cause.pretty` text, verbatim, in the reason block |
| Error state (next step) | The Restart timeline button. If it stops again, the reason names the cause |
| Empty state | No new copy. The Log's existing "No decisions to show." and the other screens' own empty messages stay: each is true as of the entries kept, and the notice above explains why nothing more is coming |
| Destructive confirmation | none: Restart discards nothing, and is idempotent |

## Component 2: the focus indicator

### Targets

The indicator applies to every element the dock focuses programmatically, and nothing else:

| Target | Why it is focused | Where |
|--------|-------------------|-------|
| Services screen root (`qadi-services`) | After Diagnostics Restart | `diagnosticsRootProps` |
| Questions screen root (`qadi-questions`) | After Diagnostics Restart | `diagnosticsRootProps` |
| Dock body (`qadi-dock-body`) | After Timeline Restart (new this phase) | `DevtoolsDock.tsx` |

Tab-stop controls (the toolbar buttons, the input, the Log rows, the reason `<pre>`, the Restart buttons)
keep the browser's default focus ring. They are tab stops, so the browser's own heuristic and exemption
apply; widening this to a shared `focusRing` token across the whole dock is a larger change and is **out of
scope**, recorded as a follow-up (the research's item 3). The Restart button sits inside the amber box, where
the default ring's white halo is 12+:1 against N, so it is not a visibility risk.

### The indicator (locked)

| Property | Value |
|----------|-------|
| Width | `2px` solid |
| Colour | `colors.accent` `#4ea1ff` (an existing token) |
| Offset | `outlineOffset: -2px` (inset), so the ring draws inside the target's box and the `overflow: auto` body cannot clip it at an edge |
| When | only when `element.matches(":focus-visible")` at the time of `focus`. A keyboard-initiated or keyboard-follow-on programmatic focus shows it; a mouse click does not, which reproduces the browser's own heuristic |
| Cleared | on `blur`, both `outline` and `outlineOffset` set back to `""` |
| Mechanism | one package-private helper, `focusRingProps`, that returns `{ onFocus, onBlur }` writing `event.currentTarget.style.outline` and `.outlineOffset` through the CSSOM. `diagnosticsRootProps` spreads it, and the dock body spreads it. No stylesheet, no `<style>` element (the package is `"sideEffects": false` and inline-only, `theme.ts` header), no React state. CSSOM writes are CSP-safe, where an injected `<style>` is not |
| Where DOM is touched | in `@qadi/devtools` only (AGENTS.md §13: `@qadi/react` calls no DOM API) |

`diagnosticsRootProps(status).style` stays `{ padding: 12 }` (the handlers are extra keys and the existing N8
and N10 assertions keep passing); the ring is written onto the live element and React's own `style` prop never
holds `outline`, so a re-render cannot wipe it.

The ring draws in the padding band of the two screen roots (12px of padding, ring 2px). On the dock body,
which has no padding of its own, the ring covers the outermost 2px of content; every row and table cell there
carries at least 8px of horizontal padding, so no glyph is covered.

### Contrast and WCAG 2.2

All against the one palette, computed 2026-11-12:

| Criterion | Level | Verdict |
|-----------|-------|---------|
| 2.4.7 Focus Visible | AA | Pass: a visible indicator exists on every programmatic target for keyboard focus. It is author-controlled, so it does not depend on the browser's default ring being legible on the dock's painted `#14161a` |
| 1.4.11 Non-text Contrast | AA | Pass: `colors.accent` on `colors.surface` is **6.78:1** (needs 3:1); on `colors.surfaceRaised` 6.18:1; on N 5.56:1 |
| 2.4.11 Focus Not Obscured (Minimum) | AA | Not at risk: nothing in the dock overlays a focused target (the toolbar is a flex sibling). The 45vh dock can cover host content, which is the host's concern for a development tool and not this phase's |
| 2.4.13 Focus Appearance | **AAA, noted only** (not required at AA) | Met anyway: the ring is 2 CSS px thick, fully surrounds the target (perimeter at least that of the unfocused box), and the focused pixels change from `surface` to `accent` at 6.78:1 (needs 3:1) |
| Both themes | n/a | One palette (see Scope). No light theme exists; a light host page is behind the dock's own `surface`, never adjacent to the ring |

Pinned by a token test (`theme.contrast.test.ts` over a new `contrast.ts` helper, reading `colors` and
`withAlpha` as the source of truth) asserting the ring `>= 3` on `surface`, `surfaceRaised` and N, and
printing the computed ratio on failure; and by a DOM test (`DiagnosticsNotice.test.tsx` `N12`, happy-dom,
where `el.matches(":focus-visible")` is true after `focus()`) asserting the outline and offset on focus and
their removal on blur, and that a never-focused root has none. The real-browser appearance stays a recorded
human backstop (UI Considerations).

## Component 3: the hardened Restart button

Applies to the one shared stopped box, so the **Diagnostics** Restart and the **Timeline** Restart change
together and cannot drift. The button is `button(false)` with two overrides and no new token:

```ts
{ ...button(false), color: colors.text, border: `1px solid ${colors.error}`, marginTop: 8 }
```

(`border` as the one shorthand, not `borderColor` beside it, so React never sees a shorthand/longhand
conflict across a re-render.)

| Part | Token | Ratio against N | Needed |
|------|-------|-----------------|--------|
| Text | `colors.text` `#e6e8ec` | **12.10:1** | 4.5:1 (1.4.3; 11px at weight 400 is not "large text") |
| Border | `colors.error` `#e3a008` | **6.57:1** | 3:1 (1.4.11, the control's boundary) |

Before the change the text was `colors.textMuted` at 4.81:1, which passed with 0.31 of margin, and the
border `colors.border` at 1.11:1, which 1.4.11 does not require when a control has visible text ("a border or
other indication of the overall boundary ... is not required"). The change is for margin and affordance, not
a failing grade: the Restart button is the single action on a fault, and on an amber tint a grey ghost button
read as disabled. Amber text-on-amber would be wrong (it would read as a second lead phrase), so the text is
the body colour and the amber is the border only.

Background stays `transparent` (the notice tint shows through), so the ratios above are against N. Nothing
else about the button changes: size (`2px 8px`, 11px, weight 400), radius 4, no hover style (the dock has
none), no disabled state, visible text is the accessible name.

Pinned by `theme.contrast.test.ts`: Restart text on N `>= 4.5` and Restart border on N `>= 3`, next to the
focus-ring ratio, so a later token change cannot regress any of them.
