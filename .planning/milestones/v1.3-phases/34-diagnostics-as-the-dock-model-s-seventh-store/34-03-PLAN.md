Rebuild public `useTimeline` on a scoped timeline feed held by `useScoped`, extracted from the dock model so the dock and
the hook share one implementation (D-15), and introduce the one store-snapshot hook it reads through (D-14). After this
plan `useTimeline` no longer uses `useRunningStore`; its remaining callers are `useDiagnostics` (34-06) and the two
keep-alive hooks `useDockSession` and `useExplorerSession` (34-04).

shape ADR-QD-137 point 7 left alone; moving it onto a scope completes ARCH-74's rule across the package. The behaviour that
changes on purpose (a fresh timeline after a remount; one stable store across a capacity change) was pinned in 34-01 and
is flipped here, in the same commit, assertion by assertion.

## Flagged assumptions

- **No consumer depends on `useTimeline`'s per-capacity store identity** (34-RESEARCH A2; no use in `examples/` or
  `packages/`). The stable store mirrors `DockModel`, which already keeps one store across a capacity change. Recorded as
  Breaking because it is observable. Reversible.
- **The placeholder is inert, not a lazily created real store.** A shared live `makeTimelineStore()` at module scope
  could be fed by a caller (`store.accept`) and leak between components; an inert one cannot. On that one pass a caller's
  `accept` does nothing. Reversible.
