## Implementation Decisions

### DEBT-01: balanced arm order
- `ab.sh` refuses an odd round count in both modes (the run and `--print-order`), with the usage text naming the reason.
  The header comment is corrected.
- A bench already recorded keeps its record. Phase 68's run of record used 3 rounds, and `68-BENCH.md` and
  `bench/final/` are **not edited**. This phase's SUMMARY names that run as the one unbalanced record.

### DEBT-02: the analyzer fails loudly
- Exit codes: `0` gate pass, `1` gate fail, `2` incomplete or refused input. The header comment says exactly this. Grep
  every caller and every text that describes the exit code (phase plans in `.planning/` are history, not callers),
  and fix any live one.
- `--self-test` runs inside a step `pnpm check` already runs. If no existing step can carry it honestly, a new step is
  added to `check` **and** the DoD table (`spec/process/definitions-of-done.md`, gate 11 `scripts/check-dod-table.mjs`)
  in the same commit. The planner picks one and states why. The self-test gains cases for exit 1 on fail and 2 on
  refusal.

### DEBT-03 / DEBT-04: Phase 68's record scripts
- **Phase 68's scripts stay as recorded.** The corrected scripts are new files in this phase's directory:
  `68.1-stale.mjs` and `68.1-compare.mjs`. They are copies of the originals with the fix. A record keeps the tool that
  produced it.
- **Staleness.** A rename or deletion after the covered commit counts as a change to the old path
  (`--name-status`, or `--no-renames`). `PATH` also matches `.changeset/…`, `.github/…` and root dotfiles. The script
  carries a self-test that plants a rename and fails on the original's logic.
- **Comparison.** Tokens come from the TypeScript source itself, with types kept and comments dropped, and titles still
  masked. They do not come from the `transpileModule` output. The script carries a self-test in which a type-only edit
  is reported as a code change.
- **Re-check.** Run `68.1-stale.mjs` over Phases 62–67 at the current head. Each phase it names is re-verified the
  Phase 68 way (`68-reverify.mjs`, a section appended to that phase's `VERIFICATION.md`, `covered_digest` replaced),
  until the result is `redo: none`. Re-run every verdict Phase 68 recorded with `68-compare.mjs`; find them in the 68
  SUMMARYs, `68-REVIEW-FIX*.md` and `68-SECURITY.md`. Record each verdict, old and new, in
  `68.1-RECHECK.md`. A verdict that flips is a finding: fix the code or the record, never the script.

### DEBT-05: gate 14 starts no unbounded child
- The probe guard's parse (`typescript/unstable/sync` `API`) moves into a child Node process run with
  `execFileSync(process.execPath, …, { timeout: CHILD_TIMEOUT_MS })`. The child prints `{ typed, refused }` as JSON, or
  a failure the parent reports through `why(error)`. Every check the guard makes today stays identical, including the
  "could not load or run the TypeScript parser, typescript@<v>" failure naming the installed version.
- The planner chooses where the child's code lives: a small module under `scripts/lib/`, or the same file in a
  child mode. It must not ship a test hook in the gate. The hang is shown in a scratch copy, with a replaced child and a
  short timeout: on the base it hangs, and after the fix it is killed and reported.
- **Texts that must say what the code holds afterwards:**
  - `check-package-install.mjs:88`;
  - ADR-QD-033 line ~171 ("the API takes no bound, so a hang there still hangs the gate");
  - any AGENTS.md §16 or `spec/` sentence. Grep for "unbounded", "no bound", "has none" and "hang".
