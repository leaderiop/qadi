# Phase 47 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** This is a refactor with a **no-visual-change contract** (CONTEXT D-08). The `@qadi/devtools` Services panel
(`packages/devtools/src/react/ServicesPanel.tsx`) must render **byte-identical** text, with identical markup, styles and
`data-testid`s, for all five ports. Surfaces touched, all internal:

- `react/ServicesPanel.tsx`: `describeOne` (:268) is replaced by a generic dispatch through the new port-reading module
  (D-05, D-06); `describe` (:304), `stateOf` (:323) and the consequence line (:188) keep their output.
- `model/Wiring.ts`: `CONSEQUENCES` (:127) and `isDefaultName` (:143) are deleted; `portRow` (:145) reads defaultedness
  through core's `isPortDefault` and the consequence through the port-reading module.
- `model/PortCalls.ts`: `ROWS` (:253) is built from the registry (D-07).

**The one user-visible change is the fix** (D-09, D-14): a hand-written wrapper that spreads `...inner` around a port's
fail-closed default, and renames it, now reads as **defaulted** in the Services panel and the wiring report. Before, it
read as a real adapter (`defaulted: false`). A wrapper that builds a fresh object (no spread) still reads as a real
adapter (D-04, a documented limit, not a defect).

**Design tokens: none added, none changed.** Every colour, font, size and spacing value below is an existing token from
`packages/devtools/src/react/theme.ts` or an existing inline literal in `ServicesPanel.tsx`. No new component, glyph,
state or interaction is introduced. Phase 34 (`2775b729`) and Phase 36 (`56c47bfd`) contracts for the dock remain in force.

## Copywriting Contract

All strings below are **verbatim from the base** (read from `Wiring.ts` and `ServicesPanel.tsx` at commit `538ff226`).
The planner pins them in characterisation tests committed alone, green on the base, before any `packages/*/src` edit
(D-11). After the refactor they must be unchanged. Source of truth after the refactor: the port-reading module's row per port.

### Consequence line, per port (`CONSEQUENCES`, `Wiring.ts:127`)

| Port | Consequence (verbatim) |
|------|------------------------|
| AttributeResolver | `a missing attribute resolves to undefined, so an attribute policy denies` |
| DecisionHistory | `the three-valued default denies hasActed and hasNotActed alike` |
| RelationshipResolver | `an unanswered relationship denies` |
| CustomPredicate | `every hasCustom node denies, since no registered predicate can be reached` |
| SignatureHistory | `an unwired signature history answers no signatures on file, so every hasSignature node denies` |

### Consequence line voice (`ServicesPanel.tsx:188`)

| Card state (`port.defaulted`) | Rendered text |
|-------------------------------|---------------|
| `true` (defaulted) | `{consequence}` (amber, `colors.error`) |
| `false` (real adapter) | `if defaulted: {consequence}` (muted) |
| `undefined` (port absent) | `{consequence}` (muted) |

### Card state text (`stateOf`, `ServicesPanel.tsx:323`)

| Condition | Rendered text |
|-----------|---------------|
| not present, required | `not provided to this reader` |
| not present, not required | `absent` |
| present, name `undefined` | `wired, unnamed` |
| present, `defaulted === true` | `defaulted — {name}` (em dash, U+2014) |
| present, otherwise | `{name}` |

The `name` shown is the composed display name (BEH-QD-196 `"<inner> (<suffix>)"`, e.g. `AttributeResolverNone (retrying)`).
It stays a display string only; nothing parses it (D-13).

### Call-row reading, per port (`describeOne`, `ServicesPanel.tsx:268`)

`describe(call)` = `describeOne(call)`, plus ` · {n} attempts` appended when `call.attempts !== undefined && call.attempts > 1`
(the literal is always the plural `attempts`, including for 2; `{n}` is `String(call.attempts)`).

| Port | Template (verbatim, every branch) |
|------|-----------------------------------|
| AttributeResolver | `{attribute \| "not recorded"} → {resolved: undefined → "no answer", true → "a value", false → "nothing"}` |
| DecisionHistory | `{event \| "not recorded"} {resourceId undefined → "anywhere", else "on {resourceId}"} → {answer \| "no answer"}` |
| RelationshipResolver | `{relation \| "not recorded"} on {resourceId \| "no resource"}{depth undefined → "", else " (depth {depth})"} → {answer \| "no answer"}` |
| CustomPredicate | `{name \| "not recorded"} → {answer: undefined → "no answer", true → "true", false → "false"}` |
| SignatureHistory | `{meaning \| "not recorded"}{signerRole undefined → "", else " from a '{signerRole}'"}{resourceId defined → " on {resourceId}"; else scope === "Any" → " anywhere"; else ""} → {matched: undefined → "no answer", true → "matched", false → "no match"}` |

Characterisation minimum per port (D-11): one call with every field present, one with every field absent, one per
distinct branch above (for SignatureHistory: `resourceId` set; `resourceId` absent with `scope: "Any"`; `resourceId` absent
with another scope), and one with `attempts > 1`. A call row also keeps its sibling spans, unchanged: `translation` /
`served` label (only for the `toPredicate` / `remote` interpreters), `{durationMillis.toFixed(1)} ms` or `in flight`.

### Other panel copy, unchanged (not touched, listed so the tests do not drift)

| Element | Copy |
|---------|------|
| Primary CTA | none (read-only panel; this phase adds no control) |
| Empty state (no calls recorded, collector on) | nothing rendered (`calls.length === 0` returns `null`) |
| Empty state (collector not wired) | `What each call asked is not shown — pass portCalls from collectPortCalls to read it from the spans.` (`portCalls` and `collectPortCalls` in `<code>`) |
| Activity, none | `never called` (or `no activity reading` when unsampled) |
| Overflow | `and {n} earlier` (cards show `SHOWN_PER_PORT = 5`, newest first) |
| Error state | not applicable; the panel's stopped/diagnostics notice is Phase 34/36's and is unchanged |
| Destructive confirmation | none in this phase |

### Wiring-report doc comment (non-rendered, listed for the executor)

`PortReport.defaulted`'s JSDoc (`Wiring.ts:60-70`) currently says defaulted is "derived from `name` for display" and that "a
host that names its own adapter after a default is reported as defaulted". After this phase that sentence is **false** and
must be rewritten: defaultedness is core's structural fact read through `isPortDefault`; a name never decides it; a
wrapper that spreads `...inner` is reported defaulted, a fresh-object wrapper is not (BEH-QD-571/572).

## Interaction and Accessibility

No interaction is added or changed. The card is non-interactive text; the panel root keeps the Phase 36 focus ring and
`data-testid="qadi-services"`. The following test hooks are a **stable contract** and must not change, because the
characterisation tests and the RED rows read them:

`qadi-port` (with `data-port`, `data-defaulted`), `qadi-port-state`, `qadi-port-activity`, `qadi-port-consequence`,
`qadi-port-calls`, `qadi-port-call`, `qadi-port-call-interpreter`, `qadi-port-call-duration`, `qadi-port-calls-more`,
`qadi-calls-uncollected`.

`data-defaulted` is `undefined` (attribute absent) when `port.defaulted` is `undefined`, else `"true"` / `"false"`.
Contrast ratios are those of the existing tokens and are not re-derived here (no colour changes).

## Module Contract (what the planner pins, from CONTEXT D-05..D-07)

Not visual, but it is what keeps the copy above single-sourced:

- One devtools module keyed by `PortName` (`model/PortReading.ts`, name at the planner's discretion) with a mapped type
  `{ readonly [K in PortName]: { consequence: string; describe: (call: PortCallOf<K>) => string } }`. The five rows hold
  the verbatim strings above. A sixth port without a row is a compile error (PFCT-05, D-12 scratch evidence).
- `ServicesPanel.tsx` keeps only `describe(call)` (dispatch plus the `attempts` suffix). No port's span field names remain
  in the view. `CONSEQUENCES` and `describeOne`'s arms are deleted.
- `ROWS` is built once at module scope from the registry; `ROWS[K]` still returns `PortCallOf<K>`; no `as`, `!` or `any`.
- Core carries no display prose.
