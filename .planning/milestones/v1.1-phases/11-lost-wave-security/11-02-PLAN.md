<objective>
Close the live guardApi bypass: the middleware decides membership by the string `group/endpoint`
(`endpointMemberKey`, `packages/http/src/AuthorizeRequest.ts:41-56`, read at `RequirePermissionMiddleware.ts:90`), and then
reads the access declaration from the **served** endpoint's annotations. So `HttpApiBuilder.layer(B)` with
`guardApi(A)` provided serves B's endpoints whenever B reuses A's names: B's public endpoint to anyone, B's write
endpoint to a writer, an API-level requirement ignored, and `/__permissions` listing A's paths, not the served ones.

After this plan `guardApi` builds a closed **access plan** from the API value it was given, keyed by the group and
endpoint *values*, and the middleware only looks an endpoint up in it: not in the plan → 500 and one log line. An
undeclared endpoint is refused when the layer is built (`AccessNotDeclared`), not at request time.

Ported from lost commit `2ea89d6` (D-03) onto merged ARCH-46's request-enforcement module: `enforceRequest` and
`answerInChannel` stay; only the string membership merged ARCH-46 centralised is replaced (its "D-46-e" row in
ADR-QD-108 is amended in 11-06). The readers (`endpointAccess`, `misplacedDeclarations`) stay exported from
`RequirePermission.ts` in this plan; 11-04 makes them private. Spec and overview are 11-06; changesets 11-07.

SEC-06 and the CONTEXT's prefix probe. The probe wires `guardApi(ApiA)` to `HttpApiBuilder.layer(ApiA.prefix("/v1"))`: on
the base `/v1/a` is served (reader 204) while `/__permissions` lists `GET /a`. That exact wiring is a RED row of Task 1
(`SamePrefixed`). After the fix `/v1/a` answers 500 and logs once, so nothing is served that the registry does not list.
The registry still lists `GET /a`, which that wiring does not mount. Removing it is not possible here: registration
happens when `guardApi`'s layer is built, from the value it was given, and `HttpApiBuilder` never tells the middleware at
build time which API value it serves. The middleware is a per-request function (`node_modules/effect/dist/http-api/HttpApiBuilder.js:500-546`
resolves it per endpoint and calls it per request). So a vetted path that is never mounted stays listed; this is the
ARCH-36 accepted residual, and the SUMMARY must say so. What this plan guarantees is the safety half of SEC-06: every
served path is listed, and every listed path is enforced wherever it is served. The correct prefix wiring,
`guardApi(P)` on `layer(P)`, lists exactly `GET /v1/a` (Task 1's pin). SEC-06's "exactly" needs that amendment, which is
flagged to the coordinator.

| `/__permissions` → operators and auditors | The listing is read as the statement of what is enforced |
