Planning-time facts (HEAD 1721a42; Phase 13 plan 13-C moves the cache's metric into `EvaluationMetrics.ts` first, so find code by identifier):

- `packages/core/src/DecisionCache.ts`: `decisionCacheLayer(options?: { capacity?: number })`; inside its closure `inFlight: HashMap<Question, InFlightClaim>` (`InFlightClaim = { claim: Deferred<Trace, EvaluationError>; fiber: Fiber | undefined; waiters: number }`), `awaitShared(entry)` = `Deferred.await(entry.claim)` with an `onInterrupt` that decrements `waiters` and, at 0, `Fiber.interrupt(entry.fiber)`; `getOrCompute` claims or joins in one synchronous step under `Effect.uninterruptibleMask`, forks `compute` with `Effect.forkDetach`, and its `onExit` writes `entries` (if the generation is unchanged), removes the `inFlight` entry by identity, then `Deferred.done(entry.claim, exit)`.
- The gap, as the doc comment above `awaitShared` states it: when `compute` is parked inside a port's uninterruptible region, `Fiber.interrupt(entry.fiber)` only records the interrupt; the entry stays in `inFlight`; a fresh ask joins it; when the region ends the interrupt lands, `onExit` completes `claim` with the interrupted exit, and the fresh joiner's `awaitShared` resolves interrupted though nobody interrupted it.
- **Pitfall:** `Fiber.interrupt` awaits the target's exit. Interrupting the claimant runs `awaitShared`'s `onInterrupt`, which calls `Fiber.interrupt(entry.fiber)`, which cannot finish while that fiber is parked uninterruptibly. Awaiting `Fiber.interrupt(fiberA)` in the test body therefore deadlocks until the gate opens. Fork the interrupt instead.
- **Pitfall:** `Effect.result(Fiber.join(f))` does not capture an interruption (it re-raises it into the test fiber). Read the joiner's outcome with `Fiber.await(f)` (an `Exit`) and assert on `Exit.isSuccess`, or on `Cause.hasInterruptsOnly` for the diagnostic message.
- Test file conventions: `packages/core/test/DecisionCache.test.ts` imports `Deferred`, `Fiber`, `Ref`, `Layer`, `AttributeResolver`, `decisionCacheLayer`, `evaluate`, `testLayer`, `subjectWith`; `needsLookup = P.hasAttribute("clearance", M.gte(1))` and `alice` are in the top `describe`'s scope. The two pins are at ~:1241 and ~:1355; append after them, inside the same `describe`.
