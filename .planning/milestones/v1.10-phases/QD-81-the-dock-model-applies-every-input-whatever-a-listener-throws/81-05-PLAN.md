<objective>
Close the begin-to-fork window at every site and run the timeline feed's two steps through `callAll` (COLL-05, COLL-03).
**D-09:** the work a status announces starts whatever a listener throws on that status, and the throw is rethrown after
it started; TF29's recorded flip lands. **D-08:** the timeline feed's steps read `held` when they run (TF37).

**Decided autonomously at planning (2026-11-24), refining D-09's mechanism:** `callAll` is used where two or more calls
can throw (the timeline feed's `configure`: a timeline listener on the resize and a status listener on the `Reading`).
At a publish-then-fork site only the publish can throw: `SupersedingRun.fork` (`SupersedingRun.ts:115-132`) returns a
boolean, and the run it installs reports a failure through its own exit and `onFailure`, never by throwing out of
`fork`; `runSource`, `runDiagnostics` and `land` build their effects lazily. A `callAll` message there would never be
read, so its string mutant would survive and no test could kill it, which D-12 and D-03 forbid. Those three sites are
`try { publish } finally { fork }`, which is `callAll`'s one-thrower answer with no message. ADR-QD-194 (81-07) records
this.

Output: `fix(81-05): the timeline feed starts its read whatever a listener throws` and `fix(81-05): the diagnostics poll
and the simulation run start whatever a listener throws`, and `81-05-SUMMARY.md`.
