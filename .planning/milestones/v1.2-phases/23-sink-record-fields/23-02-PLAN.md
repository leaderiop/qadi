Verified at planning time (HEAD `965ff14c`):

- Today's v2 field order (byte identity depends on it). Decision: `_tag, version, evaluationId, at, subjectId, policy, resource, action, cache, outcome`. Obligations: `_tag, version, evaluationId, at, outcome, obligationIds, subjectId, action, resourceId`. `Schema.Struct` encode emits keys in field order and drops excess keys (tsx probe), so `{ ...record, version: 2 }` encodes in this order whatever the record's own key order is (`Data.TaggedClass` puts `_tag` last; `Data.ts:94-100`).
- `Schema.optional(S)` is `optionalKey(UndefinedOr(S))` (`Schema.ts:2434`): Type `?: T | undefined`, which is what the records declare today. Encoding keeps a present-`undefined` key as an own key of the value; the phase keeps the value free of such keys (D-04). Candidate tools: `SchemaTransformation.transformOptional` (`SchemaTransformation.ts:553`), `SchemaGetter.transformOptional` (`SchemaGetter.ts:967`).
- `SubjectIdSchema` and `ResourceIdSchema` (`Identity.ts:45-53`) are `Schema.String.pipe(Schema.fromBrand(tag, nominal))`, already used by `Errors.ts:55`. Their encoded side is `string`, so `SinkRecordJson`'s type is unchanged (23-01's tstyche pin checks it).
