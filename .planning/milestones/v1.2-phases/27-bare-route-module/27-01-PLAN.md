- `GuardedHandler<P, A, R> = (authorized: Authorized<P>, resource: A) => Effect<HttpServerResponse, HttpEnforcementFailure, R>` (:92-95). The handler's success type is fixed to `HttpServerResponse` (unlike `guardRoute`'s free `B`).
- `HttpRouter.add` returns `Layer<never, never, HttpRouter | Request.From<"Requires", Exclude<R, Provided>> | Request.From<"Error", E>>` (`node_modules/effect/src/http/HttpRouter.ts:579-589`). `Request.From<K, R> = R extends infer T ? Request<K, T> : never` (:925) is **distributive**, so a union requirement becomes one marker per member, and `From<"Error", never>` is `never`. The namespace has an extractor for a kind's payload, `Request.Only<Kind, A>` (:935); prefer it if it reads more clearly than `Extract`.
- Why the `"Error"` extract can tell the kinds apart (re-read at revision on `a329dec0`): `interface Request<Kind extends string, T>` (:904) declares `readonly kind: Kind` (:906) and `readonly type: T`, so a `Request<"Requires", X>` is not assignable to `Request<"Error", unknown>` and `Extract<…, Request.From<"Error", unknown>>` keeps only error markers. If an effect upgrade made `Kind` phantom, that extract would return every marker (the error test then fails loudly) or nothing (it would pass vacuously); the positive control in Task 2 catches the vacuous case.
- `PermissionRegistry.tst.ts:55-64` already asserts `Layer.Services` of an `addGuardedRoute` layer is exactly `HttpRouter.HttpRouter | PermissionRegistry | HttpRouter.Request.From<"Requires", StandingEvaluationServices | SubjectExtractor>`, with imports to copy.
