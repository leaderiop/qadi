Invariant line: link INV-QD-241 and INV-QD-006, using the anchors in the interfaces block.

Two plain-fenced REQUIREMENT blocks:
(1) `portRoutes`, `portRoutesUnguarded` and `remotePortsLayer` MUST build a port's path from one definition, `<prefix>/<PortName>`, whose prefix defaults to `/__ports` on both sides. A host that gives the routes and the client the same `prefix`, or neither, MUST be answered for every port it serves.
(2) `remotePortsLayer` MUST read the reply from the response body whatever the HTTP status. An `Answered`, `Unavailable` or `Refused` body is that reply under any status. A body that is not a reply (a proxy's HTML error page) MUST be the port's own error, never an answer. The status, from `PORT_REPLY_STATUS`, is for the layers in between.

Prose, fact first, then the why:
- The definition is `packages/http/src/PortRouteAddress.ts` (`PORT_ROUTE_PREFIX`, `portPath`). It is package-private (ADR-QD-099), so a host names a prefix only through `PortRoutesOptions.prefix` and `RemotePortsOptions.prefix`.
- The reply-body contract is stated beside the address, and `PORT_REPLY_STATUS` in `PortRoutes.ts` points to it.
- Why: the 2026-11-08 architecture review (ARCH-52) found that each adapter declared its own default prefix and built the path inline. A change to one would have made every remote read a 404 with no reply body: fail closed, because the client reports it as the port's own error, but every re-check broken.
- `packages/http/test/PortRoutes.test.ts` pins it: a round trip under `/x/ports` for both route forms and every port, the default path absent and a default-prefix client failing, and three canned responses for the status contract.
- The route design itself is ADR-QD-107's.

Do not add a ` ```typescript ` fence. The module is package-private and cannot be imported from `@qadi/http`. A ` ```ts ` listing of `portPath`'s signature is allowed if you mark it package-private.

Then run `node scripts/spec-revise.mjs spec/behaviors/23-http.md "BEH-QD-<id>: the port routes and their client share one address, and the client reads the reply from the body whatever the status (ARCH-52, CCR-QD-391)"`.
