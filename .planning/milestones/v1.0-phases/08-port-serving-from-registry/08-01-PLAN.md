  <decision>Approve or reject amending ADR-QD-094 so that a port description states a `serving` facet: its allowlist kind (required, open or opt-in), the policy leaf tags it answers (each with the name that leaf asks), and the name a served request asks (today's `wire.asked`).</decision>
  <context>
In favour. "Which leaf asks which port" is stated in six places: `PortServing` (PortRemote.ts:52), `ADMITTED` (:67), each port's `wire.asked`, `Collector` (:226), `collectNames` (:241) and `servingFor`'s five sets (:206-224). Adding a leaf or a port touches all six, and only two of them are compile-checked. A forgotten `collectNames` arm compiles. It makes `servingFor` omit a name, so a client's re-check of that leaf fails as `NotServed`. That fails closed, but nobody is told. With the facet, a port's description states it once, and the other five derive from the registry. Serving is a fact about the port (what a server may answer about it), not test data. A probe showed it typechecks without `as` and keeps `servingFor`'s output identical.

Against. ADR-QD-094 kept descriptions behavioural. Its CCR-QD-270 amendment rejected a `fixture` field because it "would put a test-data shape into every production description and break every literal". A `serving` member is also a new required member: it is breaking for anything that builds a `PortDescription` by hand, though unreleased, since it ships in 0.12 beside the also-new `wire`. Descriptions grow by one facet. The facet's leaf map names `Policy` leaf tags, so a port module's description now refers to the policy ADT, which it did only through `RelationshipDepth` before.

Not affected by your choice: plan 08-02 removes `mapPorts` (merged into `tabulatePorts`), derives `fixturePortsLayer` from the registry, and removes `@qadi/testing`'s `answersOf`/`layersOf` split. It ships either way (D-07..D-09). If you approve, plans 08-03 (code) and 08-04 (ADR-QD-114 and amendments) run, and 08-05 skips. If you reject, 08-05 records your reason in ADR-QD-094 as a dated "Considered and rejected" note so future reviews stop suggesting it (D-06), and 08-03 and 08-04 skip.
  </context>
