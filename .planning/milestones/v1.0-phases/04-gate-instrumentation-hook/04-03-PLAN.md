The per-kind table states which kinds wrap a marker and which carry the entry name in their id. Registration goes through `useGateRegistrations`.
   - `useGate`, `useQuestionsAs` and `useDecisionSuspense` are thin callers; the last suspends on the atom its gate opened (D-03, D-04).

It may therefore import neither, nor `GateRegistry.ts`, without a cycle (ADR-QD-037). So the scope is typed structurally (`GateAtoms`), and `MissingQadiProviderError` moved to a leaf that `QadiProvider.tsx` re-exports by name.

   **Decisions taken (ARCH-49)**: a table D-49-a to D-49-h mapping one-to-one to the CONTEXT's D-01 to D-08, each with the choice as implemented.

   **Consequences**:

   - The D-07 finding, with the counts from 04-02's SUMMARY.

A group-atom identity would re-register siblings, against BEH-QD-068's "MUST unregister exactly an instance whose name is dropped". So the one per-entry lookup lives in `useGates`, memoised on the group, and `useQuestionsAs` looks up nothing.

   - The hook in `useGate.ts`, reading `useQadiContext`: no cycle, but D-02 puts it beside the registration lifecycle.
   - A writer field on `QadiContextValue`: it publishes the writer.
   - The group atom as each entry's identity: it breaks BEH-QD-068.
   - An `Equal`-keyed identity token in the hook: a second notion of question identity beside the question book's.
   - A per-kind read: the one-question kinds would read their decision atom, but that needs a hook call chosen per kind and a value union that only a cast could narrow.
