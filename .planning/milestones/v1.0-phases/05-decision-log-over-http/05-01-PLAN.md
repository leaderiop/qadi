<objective>
Give the HTTP side of the decision log one internal module, `packages/http/src/DecisionLogHttp.ts`. It encodes a decision-log read as SSE frames or as a JSON array and owns refusal reporting: a refused record drops only its own frame or element, and `onRefused` is told (LOGH-01, D-01). Both routes go through it, and neither restates refusal logic (LOGH-02, D-02). The backlog route stops importing from the stream route (LOGH-03, D-03). One table-driven test covers refusal in every framing (LOGH-04, D-06).

Purpose: ARCH-50. Each of the two routes holds a refusal reporter and an encode-or-report loop, and the two copies differ only in their message and span name. The next adapter would copy a third. After this plan the refusal policy for both framings has one owner in `@qadi/http`. The policy's substance (hook or warning, containing a throwing hook, the annotations) stays core's `reportEncodeRefusal`, per ADR-QD-095 D-09-e and CCR-QD-193. SinkCodec is unchanged (ADR-QD-095/097).

Tracer first: Task 1 proves the module end to end on one framing. That framing is JSON, through the backlog route's real handler. Task 2 expands the same module to SSE and rewires the stream route.

Output: the new module, both routes rewired, the refusal table `DecisionLogHttp.test.ts`, and the compatibility pins in `DecisionLogHttp.tst.ts`.

Design choices made at planning time (Claude's discretion; record them in the SUMMARY for Plan 02's CCR row):
- Module name: `DecisionLogHttp.ts`, as D-01 suggests.
- `frame` moves into the module, and `DecisionStreamRoute.ts` re-exports it by name. This is required: D-01 puts the SSE encode-or-report in the module and builds it on `encodeStoredRecordString`, which is what `frame` wraps. If `frame` stayed in DecisionStreamRoute.ts, the module would import DecisionStreamRoute.ts while DecisionStreamRoute.ts imports the module, a cycle that `pnpm circular` (madge) refuses. The re-export keeps the public name, the barrel and every `../src/DecisionStreamRoute.ts` import path (tests, DecisionStreamRoute.tst.ts) working, so D-02's "DecisionStreamRoute keeps the SSE framing" holds at the public surface.
- `syncedFrame` stays in DecisionStreamRoute.ts. It carries no record and cannot be refused. It belongs to the stream protocol (prelude, synced, live; ADR-QD-097), which D-02 keeps with `decisionFrames`. It reuses core's `DecisionStreamSynced` and `DecisionStreamEvent` vocabulary (ARCH-28, CCR-QD-195), which is unchanged.
- Options (D-01, D-04): the module declares `DecisionLogServeOptions` (`onRefused` only). `DecisionStreamOptions` stays declared and exported in DecisionStreamRoute.ts as `DecisionStreamOptions extends DecisionLogServeOptions`, adding `reauth`. Its name and source module do not change, so its overview row keeps its Source. The new interface is not exported from the barrel, so no export is added (patch, D-07). It is structurally identical to `Pick<DecisionStreamOptions, "onRefused">`.
- Wording (D-01, "message and span name as parameters"): one `reportRefused` factory, applied once per framing at module scope with today's exact span names and messages. "One wording that covers both" is rejected. It would change two log lines that tests pin (decisionStream.test.ts:774, decisionBacklog.test.ts:157), and ADR-QD-095 D-09-e quotes "could not be framed" and keeps each adapter's own message.
</objective>
