## Flagged assumptions

- **DIAG-05 (probe: unclassified).** Read as: a defect is a closed `Stopped { reason, sampled }` state with the last reading
  kept (this plan, model), shown by a shared notice with a restart command on Services and Questions (34-07); the behaviour
  across a hidden `Activity` (the model rebuilds at `Starting`) and across `undefined` and back is pinned in M25, M26 and
  F10, F11 here, and through React in 34-05 and 34-06.
- **`sampled` means "the reading shown holds an accepted sample".** D-02's parenthetical (a stop from `Starting` is
  `false`) is literal for a first run. After a restart from `Live`, the kept reading is a real earlier sample (D-03 keeps
  it), so a stop before the new run's first sample reports `sampled: true`: the panel's copy ("the last one it took") is
  then true, and `false` ("nothing below was sampled") would be false, which D-02 exists to prevent. `sampled` resets
  only on `Off`. Reversible.
- **The run token in the marking `accept` may be unreachable.** A replaced run is interrupted synchronously after the new
  run's synchronous prefix, so a stale accept needs re-entrancy (F16 drives one: a `questions` source that calls
  `restart()` while it is sampled). If Stryker still reports that guard as a survivor, it is named in
  `34-mutation-survivors.json` with that reason, never ignored by comment or config. The guard in `onExit` is killed by F9.
- **`Cause.pretty` is kept verbatim and uncapped** (the open question in 34-RESEARCH): it lives only in the model's
  snapshot and is rendered as React text (34-07, bounded in height there); it never reaches a record, a response, a log or
  a metric. Stated in the ADR-QD-047 amendment (34-08).
