<objective>
Give the server adapter (`PortRoutes.ts`) and the client adapter (`RemotePorts.ts`) for remote ports
one definition of the route address, and one stated contract that a client reads the reply from the
body whatever the HTTP status (ARCH-52).

Purpose: today each adapter declares its own default prefix and builds the path inline, so the two
agree on the route only by coincidence. If one changes, every remote read becomes a 404 with no
reply body. The client reports that as the port's own error, so the read still fails closed, but
every re-check is broken. The round-trip test is written first (D-04), so the refactor runs under a
safety net that would catch the two sides drifting apart.

Output: the leaf module `packages/http/src/PortRouteAddress.ts` (D-01), both adapters routed through
it (D-02), the status contract moved beside the address (D-03), and the round-trip, address and
status-contract tests in `packages/http/test/PortRoutes.test.ts` (D-04).
</objective>

| Boundary | Description |
|----------|-------------|
| client → port route | An untrusted request (bearer token, JSON question) reaches `portRoutes` / `portRoutesUnguarded` at the computed path |
| network / proxy → client | A response body and status cross back. An intermediary can substitute either (an HTML 502, a cached page) |
| server config ↔ client config | The route prefix is configured separately on each side; a mismatch must fail closed |
