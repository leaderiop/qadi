Design recorded (owner: choose the most complete and clean design and record why):
- react: the name is read in its own guarded helper (an `Error`'s `name`, read inside a `try` and rendered through
  `thrownMessage`, so a non-string name reads as its `String` form, as the old template did); the line is
  `${name}: ${thrownMessage(error)}` when there is a name and `thrownMessage(error)` otherwise. This is D-08 as
  written. Noticed edge, not taken: an `Error` whose `message` is not a string reads `Error: Error: 42`, because
  `thrownMessage`'s fallback is the value's `String` form, which already carries the name. D-08 fixes the composition,
  the case is exotic, and it no longer throws; named in the summary.
- devtools: "reads `cause` first" stays (D-06). The whole rule is one expression,
  `thrownMessage(cause ?? tag ?? error)`, each of `cause` and `tag` read with `Reflect.get(Object(error), …)`: no
  `if` arm is left that a port error cannot reach, so no mutant survives on a branch no test can drive (every port
  error is tagged, and a test cannot build an untagged one without `as`). A `null` cause now reads as no cause (the tag)
  where it read `null`. With no cause, the capture records the error's `_tag` instead of `thrownMessage(error)`,
  because a port error's `message` is empty (so `thrownMessage` would record an empty string)
  and its `String` is not always the tag: `CustomPredicateError`'s `name` field holds the predicate's name, so today a
  custom predicate failure is captured as `isOwner`. The tag is what `renderError`'s doc comment already says the
  capture falls back to, and a replay rebuilds the error class from the port, so the tag is the honest record. This is
  a visible change (C2), named in the CCR row and the devtools changeset. Noticed, not taken: capturing a
  `CustomPredicateError`'s `reason` would make its replay carry the reason too; that is a capture-fidelity change
  beyond this phase, named in the summary as a follow-up.

Shell and commit rules: as in 69-01's objective. No comment may hold the inline Error-or-String ternary or the old
angle-bracketed placeholder: the negative gates count comment lines.
