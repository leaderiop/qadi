## The close

With the tree clean and nothing else running, for each group in turn (`core`, `devtools`, then `http`): run its
invocation from the base record `< /dev/null > <S>/stryker-close-<group>.log 2>&1` in the background, wait for `Final
mutation score of` in the log, then `node <D>76-mutation.mjs record close <group> < /dev/null`.

**The by-hand runs, by line.** For each group, a scratch config `<S>/stryker.examined-<group>.mjs` that spreads the
group's config with `ignoreStatic: false`, `jsonReporter: { fileName: "<S>/examined-<group>.json" }` and
`htmlReporter: { fileName: "<S>/examined-<group>.html" }`, run in the background as `pnpm exec stryker run
<S>/stryker.examined-<group>.mjs --mutate <every file of the group, comma-separated, in the scorer's order> <
/dev/null > <S>/stryker-examined-<group>.log 2>&1`, waited for through `Final mutation score of`. Every file is run,
not only those whose Ignored count grew, so a static mutant on a written line is run even when an Ignored mutant left
an unwritten one. A file's written lines are the `+` lines of `git diff -U0 <phase_base> <close head> -- <file>`. Every
by-hand mutant on a written line must be Killed or Timeout, or a RuntimeError on which every test file importing the
module fails to load, explained in the evidence under its `<file>:<line>`. A mutant on a written line that survives is
closed as a drop below and the runs repeat. Set `EXAMINED` (one line) to the counts by kind per file the scorer needs
for the Ignored mutants the close holds beyond its base, each no more than the by-hand run killed of that kind on that
file's written lines; extend its doc comment with one sentence per file saying what the admitted mutants are (the
static arrows of the expression-bodied exports `signatureAnswerOf`, `signatureAnswerFromSignatures`,
`actedAnswerFromEvents`, the module-scope `skipReason` dispatcher, the refusal sentences, `NO_CUSTOM_PREDICATE_FIELD`
and the error schemas' optional members, as found), and re-run `--self-test` (`self-test: 38 passed`, more only if a
`MOVED` entry was added with its own cases). Add `## Static mutants run by hand` to the evidence: each command, the
counts per file, the written-line ranges per file, and every mutant on a written line with its file, line, mutator,
replacement and status.

**Deleted code.** 76-04 deletes lines of `DecisionHistory.ts` the base record holds mutants on: the `HashSet` fixture
body and the `ActedEvent` and `ActedAnywhere` classes, which the keyed fixture left with no reader (the deleted
`ActedAnywhereInput` is an interface, which Stryker does not mutate, so it removes no mutant). `compare` locates
each base mutant on its close line through `git diff -U0 <base head> <close head>`; a mutant whose line was deleted has
no close line, so it is not a new mutant, and the file's score may fall only by killed mutants removed, which the
removed-mutant rule admits (the scorer logs `killed mutants removed` for the file); a deleted survivor only raises
the score. Deleted lines are not written lines, so the by-hand runs do not cover them. Under `## Static mutants run by
hand`, list the base mutants on the deleted lines (from the base report) with their status, and say which of
`DecisionHistory.ts`'s fall, if any, they explain.

Then `node <D>76-mutation.mjs compare < /dev/null > <S>/compare.log 2>&1`. If compare refuses, or a by-hand mutant on a
written line is not killed:

- a score that fell by more than killed mutants, or an open mutant a test can kill: add the test, additions only, with
  every project green, the agreement check passing and house-style clean, and commit it alone as `test(76-06): <what it
  pins>`. The test goes beside the code it pins: `SignatureHistory.test.ts` or `DecisionHistory.test.ts` (inside its
  conformance `describe` or a new appended one), `SinkCodec.test.ts` or `PortAccess.test.ts` (core),
  `SimulationFields.test.ts`, `QadiHttpError.test.ts`, or, for a `Remedies.ts` survivor, a new row in a new top-level
  `describe` appended to `Remedies.test.ts`, every existing row unchanged (D-09 freezes the rows, which
  `76-agreement-check.mjs` holds). A survivor is killed this way; it is never reported as a deviation;
- a survivor no test can kill because the condition is redundant at run time: remove the redundancy in that one
  measured source file with every suite green, commit it as `refactor(76-06): <what it removes>`, and record it under
  `## Equivalent mutants removed`;
- a survivor that moved between two files of a group (the answer rule from `PortAccess.ts` to `SignatureMatch.ts`):
  pair it through a `MOVED` entry with its own self-test cases, as `75-mutation.mjs` does, and record it.

After any commit, re-measure every group with `record close <group> --restart` on the new head, repeat every by-hand
run, and compare again. When compare passes and every written line's mutants are killed, commit
`76-mutation-close.json`, `76-mutation.mjs` and the evidence as `docs(76-06): record the mutation close of the remedy
and fixture files`.
