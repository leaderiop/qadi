## The arms

**Shared, module scope** (beside `NO_RESOURCE_ID`):

- `const SIGNATURE_PORT_REFUSED = "the signature port refuses this check, so no added row would be answered: ";` and
  `const HISTORY_PORT_REFUSED = "the history port refuses this check, so no added row would be answered: ";` (each
  string on its own line).
- `const skipReason: (failure: MissingResourceId | SignatureHistoryUnavailable | DecisionHistoryUnavailable) => string
  = Match.type<MissingResourceId | SignatureHistoryUnavailable | DecisionHistoryUnavailable>().pipe(Match.tagsExhaustive({
  MissingResourceId: () => NO_RESOURCE_ID, SignatureHistoryUnavailable: (failure) =>
  \`${SIGNATURE_PORT_REFUSED}${thrownMessage(failure.cause)}\`, DecisionHistoryUnavailable: (failure) =>
  \`${HISTORY_PORT_REFUSED}${thrownMessage(failure.cause)}\` }))`, wrapped by hand, with a doc comment: one-line summary
  "Why a remedy core's fixture judgement failed for is skipped."; then that a check the port refuses (a form row or the
  form's subject its key cannot read) is skipped with the port's refusal rather than offered a row, because the port
  would refuse the check whatever row were added, so the row would not remedy it (BEH-QD-222); and that both
  judgements read this one dispatcher, each failing with `MissingResourceId` or its own port's error. Task 1 writes it
  with all three arms; the history arm is reached once Task 2 lands.
- `const siteOf = (input: SimulationInput): ReadSite => ({ subject: subjectOf(input.subject), resource:
  input.resource })`, one-line doc: "Where the simulated check is made, as core's fixture judgements take it." `ReadSite`
  is imported as a type from `@qadi/core`.

**`Requirement`**: `{ readonly _tag: "Acted"; readonly leaf: LeafOf["HasActed"] }` and `{ readonly _tag: "Signature";
readonly leaf: LeafOf["HasSignature"] }`. `requirementCases.HasActed` becomes `(p) => [{ _tag: "Acted" as const, leaf:
p }]` and `HasSignature` `(p) => [{ _tag: "Signature" as const, leaf: p }]`; the `HasSignature` comment (`:365-367`)
says instead that the node itself goes to core, which answers whether the form's rows meet it at the site, so the
remedy reads the port's own scoping and match; a one-line comment above `HasActed` says the same of
`actedAnswerFromEvents`.

**`Signature` arm**: `(self) => (input: SimulationInput) => { const site = siteOf(input); return
Result.match(signatureAnswerFromSignatures(fieldOps("signatures").elements(input), self.leaf, site), { onFailure:
(failure) => skip(\`signature ${self.leaf.meaning}\`, skipReason(failure)), onSuccess: (answer) => answer.matched ?
undefined : <the grant> }); }`, where the grant's `resourceId` is the `resourceId` of
`signatureHistoryPort.asks.HasSignature(self.leaf, site)`'s one request and the row and the label are built as at
`:546-559` with `self.leaf.meaning` and `self.leaf.signerRole`. Its comment (`:525-530`) says instead: met is core's
answer for this node at this site over the form's rows, not a restated match; an unmet node is one row whose resource
id is the request's own, so the row carries the id exactly when the question does; a failure, a refusal included, is
skipped with `skipReason`; and the port's match ignores `signedAt`, `algorithm` and `keyId` (ADR-QD-058), which is why
this is not `sameSignature`'s full equality, the form's duplicate check.

**`Acted` arm**: `(self) => (input: SimulationInput) => Result.match(actedAnswerFromEvents(fieldOps("history")
.elements(input), self.leaf, siteOf(input)), { onFailure: (failure) => skip(\`event ${self.leaf.event}\`,
skipReason(failure)), onSuccess: (answer) => answer === "Acted" ? undefined : <the row> })`, where the row is: `const
resourceId = resourceIdOf(input.resource)`; undefined gives `skip(\`event ${self.leaf.event}\`, NO_RESOURCE_ID)`;
otherwise `edit(grant("history", { subjectId: input.subject.id, event: self.leaf.event, resourceId }, \`with event
${self.leaf.event} on ${resourceId}\`))`. Its comment says: met is core's answer, so an `Any` leaf is met by the
subject's event on any resource; a refusal is skipped with `skipReason`; an unmet node needs the site's resource id for
its row, because an event record carries one and `Any` widens the question, not the fixture.

**`remedyEdits` doc** (`:69-86`): its second paragraph says that "does not already meet" is a syntactic check for
roles, permissions and edges, set membership the lookup answers; that for events and signatures it is core's answer
(`actedAnswerFromEvents`, `signatureAnswerFromSignatures`), because the leaf's scope decides which row answers and that
rule is the port's; that a check the port refuses is skipped with the port's refusal, never offered a row and never
thrown, for any value a form row or the form's subject holds; and that the two agreement tests
(`RemedySignatureConformance.test.ts`, `RemedyActedConformance.test.ts`) compare the table with core's evaluation. The
attribute sentences and the rest stay.
