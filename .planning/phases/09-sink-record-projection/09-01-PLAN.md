<objective>
Move the obligation record's projection into `SinkEmit.ts`, beside `failedRecord` and `decidedRecord`, and make `Qadi.ts`'s `discharge` call it (SINK-01, D-01, D-02). The record's bytes do not change, and a whole-record pin proves it before and after (D-03).

Purpose: ADR-QD-100 already says `SinkEmit.ts` is "the one projection of a `Question` into a record". ADR-QD-105 (ARCH-30) then added the obligation record's identity keys and built them inline in `discharge`, so the rule "a record cannot disagree with what was asked" was stated twice. After this plan it is stated once: every sink record comes from its question in one module.

Output: `obligationRecord` in `SinkEmit.ts`; `discharge` delegating to it; pin, equality and unit tests in `DecisionSink.test.ts`.
</objective>

- `Qadi.ts` `discharge` (about lines 134-190) builds the record inline today: after the early return for an allow with no obligations it reads `sinkEmitter` and `Clock.currentTimeMillis`, computes `obligationIds = decision.obligations.map((o) => o.id)` and `resourceId = resourceIdOf(question.resource)`, and defines a local `record(outcome)` closure that constructs the `ObligationRecord` with `evaluationId: decision.evaluationId`, `at`, `outcome`, `obligationIds`, `subjectId: question.subject.id`, then the two conditional spreads `...(question.action === undefined ? {} : { action: question.action })` and `...(resourceId === undefined ? {} : { resourceId })`. The closure is called at four emit sites: `HandlerFailed` (tapError), `Discharged` (tap), `NotRequired` and `Refused`.
- Imports `Qadi.ts` will no longer need once the projection moves: the `ObligationRecord` value import (line 28) and `resourceIdOf` (line 39). `ObligationOutcome` (type, line 27) stays only if the closure keeps its annotation. `Clock` stays: the caller reads the time, as `Lifecycle.ts` does for `Stamp`.
- `resourceIdOf(resource)` (Resource.ts) returns a branded `ResourceId` only for a string `id`, else `undefined`.
- `ObligationRecord` (DecisionRecord.ts:135) is a `Data.TaggedClass("Obligations")` with `evaluationId`, `at`, `outcome`, `obligationIds` and optional `subjectId`, `action`, `resourceId`.
- No import cycle: `SinkEmit.ts` may import `Allow` (type) from `./Decision.ts` and `resourceIdOf` from `./Resource.ts`; neither module's import closure reaches `SinkEmit.ts`.
- `DecisionSink.test.ts` already has a `collecting()` sink, `allowed = subjectWith({ permissions: ["doc:read"] })`, `testLayer(allowed)` (sequential evaluation ids, `TestClock` at 0), and inside `describe("the obligation gate is recorded")` the policies `audited = P.obliged(obligation("audit.log"), P.hasPermission(read))` and `advised` (advisory `notify.owner`) plus an `obligationsOf` filter. It imports `ObligationRecord` as a type only today.
- `obligation(id)` sets the obligation's `id` to `id`, so `audited`'s obligation ids are `["audit.log"]`.
- Tests may construct `Allow` and records directly: `no-decision-constructor-outside-decision` and the other non-`testScope` house-style rules do not scan test files (`Decision.test.ts` builds `new Allow({...})`).
