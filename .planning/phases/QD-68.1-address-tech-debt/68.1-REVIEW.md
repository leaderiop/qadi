## Warnings

### WR-01: `68.1-compare.mjs` reports `same` for edits that change what compiles or evaluates

**File:** `.planning/phases/QD-68.1-address-tech-debt/68.1-compare.mjs:69-91`
**Issue:** DEBT-04 was "type-blind", but the scanner reading still drops several things that change behaviour. I reproduced each in a scratch repo with the script's own CLI, and each printed `same:` and exited 0.

- Deleting a `// @ts-expect-error` line. A comment is dropped, so the removed directive is invisible. The next compile then fails with a type error the script said was impossible.
- `[,]` becomes `[]`. The trailing-comma filter drops the comma before `]`, but `[,]` has length 1.
- `<T,>(x: T) => x` becomes `<T>(x: T) => x` in a `.tsx` file. The filter now drops a comma before `>`, but in TSX that comma is what makes it a generic arrow rather than JSX.
- A JSX text edit after a `//`, for example `<p>see http://a.example/x and more</p>` becoming `...y</p>`. In the JSX scan, text is tokenized as JavaScript, so `//` starts a comment that runs to the end of the line.

The header says the script "shows an edit changed only comments, line breaks and test titles". The first case is the realistic one for the test files this script compares. The other three are edge cases.

**Fix:** Keep the comment tokens that TypeScript reads as directives: when a comment matches `/^\s*(\/\/|\/\*+)\s*@ts-(expect-error|ignore|nocheck|check)\b/`, emit its text as a token. For `[,]`, drop a trailing comma before `]` only when the token before the comma is not `[` or `,`. For `<T,>`, do not drop a comma before `>` when it follows a bare identifier directly after `<`. Alternatively state these exclusions in the header, so "same" is not read as stronger than it is.

### WR-02: The CCR-QD-460 row says "the one bench recorded with an odd count", and there are many

**File:** `spec/README.md:397`
**Issue:** The sentence "`ab.sh` refuses an odd round count in both modes, so each arm runs first in half the rounds, and the one bench recorded with an odd count keeps its record" is false as written. The `meta.txt` files in the repository record `rounds: 3` for phases 50, 59, 65, 66, 67 and 68, and `rounds: 5` for phase 59 `gate-r2`. That is 12 benches with an odd count. Only Phase 68's was made with the shared `ab.sh`; the others ran their own copies (the `ab.sh` header names 59, 66 and 67). The row does not scope the claim to `ab.sh`.
**Fix:** Scope it: "and Phase 68's bench, the one `ab.sh` recorded with an odd count (3 rounds), keeps its record; earlier phases' benches ran their own copies of the harness." Bump the spec/README Revision and the Change History entry with it.

### WR-03: "a hung server shown killed" overstates what the planted hang showed

**File:** `spec/README.md:397` (and `spec/decisions/033-the-packed-artifact-is-the-product.md:186-187`)
**Issue:** The CCR row says the child's answers were "shown identical to the in-process parse's and a hung server shown killed and reported". The evidence in `68.1-04-SUMMARY.md` is a hook (`NODE_OPTIONS=--import`) that makes the `API` constructor block. No TypeScript server process was started, so none was killed. What was shown killed is the child. The same row then says "the gate kills only that child, so the TypeScript server the child started may outlive it", which contradicts "a hung server shown killed". ADR-033's "A TypeScript server that stops answering now ends the gate at the timeout" holds. The mechanism supports it (see the Summary), but the planted run does not demonstrate it with a real server.
**Fix:** Say "a hang planted in the child (a blocked `API` constructor) shown ending the child at the timeout and reported". Keep the "may outlive it" sentence.

### WR-04: `68.1-stale.mjs`'s dotfile alternative swallows a sentence-final period or hyphen, so a cited dotfile is not found

**File:** `.planning/phases/QD-68.1-address-tech-debt/68.1-stale.mjs:23`
**Issue:** The dotfile alternative is `(?<![A-Za-z0-9_./@-])\.[A-Za-z][A-Za-z0-9_.-]*`. Its tail class includes `.` and `-` and the match is greedy, so it has nothing that backtracks off a trailing `.` or `-`, unlike the first alternative, which must end in an alphanumeric extension. Run on the text `see .oxlintrc.json.` it returns `.oxlintrc.json.`, which is not in `ls-tree`, so the citation is dropped and an edit to `.oxlintrc.json` reads as `current`. The same happens for `.oxlintrc.json-`. The self-test misses it because its fixture ends the name in a backtick. No current VERIFICATION document is affected: I checked 62 to 68 for matches that would resolve once the trailing `.` or `-` was stripped, and found none. It is a latent false negative in a check whose job is to not have them.
**Fix:** End the token on an alphanumeric, as the first alternative does:
```js
(?<![A-Za-z0-9_./@-])\.[A-Za-z](?:[A-Za-z0-9_.-]*[A-Za-z0-9])?
```
Add a self-test case where the cited line is `see .oxlintrc.json.` with no backticks.

### WR-05: `68.1-stale.mjs`'s `PATH` still has no branch for several tracked root paths

**File:** `.planning/phases/QD-68.1-address-tech-debt/68.1-stale.mjs:22-23`
**Issue:** The phase's goal was `PATH` coverage. Tracked root paths with no alternative:

- `CLAUDE.md`. The pattern lists `AGENTS|README|CONTRIBUTING` only.
- `vitest.config.ts`. Root-level, and a phase about coverage thresholds or tests would plausibly cite it.
- `LICENSE`.
- the `assets/` and `reports/` directories.

A verification document citing any of these is never marked stale. None of the 62 to 68 documents cites them today. The pattern is again a hand-kept list that will drift.
**Fix:** Add `CLAUDE|LICENSE` to the root-file alternation and `vitest[a-z.-]*\.(?:ts|mts|mjs)`. Add `assets|reports` to the directory alternation. Better, build the pattern from `git ls-files | cut -d/ -f1` at run time, so a new root path cannot be missed.

### WR-06: `ab.sh` accepts 2 rounds, which `analyze.mjs` will refuse after the full run

**File:** `scripts/bench/ab.sh:31`, `scripts/bench/ab.sh:25-30`
**Issue:** The header says "the smallest run both accept is 4", but `rounds_ok` only checks that the count is even. `ab.sh --print-order 2 a b` exits 0, and a run with 2 rounds proceeds. `analyze.mjs` has `MIN_ROUNDS = 3`, so it refuses the result with exit 2 only after every bench round has run. Phase 68.1 set out to make the harness fail loudly. This is a failure a few minutes late, and the usage text does not mention a minimum.

### IN-01: `probe-guard-parse.mjs` has failure paths its header and the parent do not cover

**File:** `scripts/lib/probe-guard-parse.mjs:19-20`, `scripts/lib/probe-guard-parse.mjs:84-87`
**Issue:** The header says "a failure to load or run the parse writes the error's message to stderr and exits 1". Two cases differ.

- `JSON.parse(probes)` and `new Map(...)` run at module top level, outside the `try`. A malformed argument prints an uncaught stack and exits 1, not the one-line message. The parent always passes valid JSON, so this is unreachable from the gate.
- `process.stderr.write(String(error.message))` writes the string `undefined` when something other than an `Error` is thrown.

In the parent, a stdout line that is not JSON makes the `JSON.parse` throw a `SyntaxError`. `why(error)` then has no `stdout` or `stderr` to show, and the child's output is lost.

**Fix:** Move the argument parsing into the `try`. Write `String(error?.message ?? error)`. In the parent, wrap the `JSON.parse` so a failure includes the child's stdout in the message.
