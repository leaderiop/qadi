  <context>
Part 1 — the deadline (D-02). Today a store call that never settles stalls the decision that recorded it (`evaluate` awaits `sink.record` inline, by ADR-QD-044's design), and the breaker never counts it: three hung writes with `failureThreshold: 1` leave it Closed.
- A. One finite default deadline, overridable: a new `AuditDecisionSinkOptions.storeCallTimeout?: Duration.Input`, default `Duration.seconds(5)`, applied to each of stage, write and commit separately. A timed-out call is a failed attempt: a write is counted on the breaker (D-03) and becomes `WriteFailed`; a stage becomes `StageFailed`; a commit becomes `Written` with `CommitFailed`. No new public error class: the timeout reaches the outcome as the port's own typed error (`AuditWriteError`/`AuditStagingError`) whose `cause` is effect's `Cause.TimeoutError`, so `WrittenStaging.CommitFailed`'s `Cause<AuditStagingError>` type does not widen. `Duration.infinity` is the explicit opt-out and documented as such. `@qadi/audit` minor (an option is added).
- B. The same mechanism with no default: `storeCallTimeout` required, so `AuditDecisionSinkLive(options)` takes a required options object. Breaking for every caller that writes `AuditDecisionSinkLive()` (every audit test, the README, `check-package-install.mjs`'s consumer, the website's capabilities page).
- C. ADR-QD-044's own route: a buffered sink — `record` enqueues and returns at once, a flush fiber drains to the store on its own schedule. Adds zero evaluation latency, even for a slow-but-healthy store. Costs: delivery becomes asynchronous (a process that exits loses what is queued unless shutdown flushes), the queue needs a bound and an overflow policy (an overflow is a lost entry that must be counted), records stop being ordered relative to the decision under `TestClock`, and the flush fiber still needs A's deadline, or a hung store wedges the flush and the breaker still never sees it. C is therefore A plus a buffer. Choosing C runs every plan of this phase exactly as for A (14-03 ships A's deadline, 14-04's `Never` rows are bounded by it, 14-05 and 14-06 run unchanged), and 14-06 records the buffer as chosen but not built: ADR-QD-126 states the decision and the open questions (bound, overflow, shutdown flush), and the phase SUMMARY raises one blocker asking the orchestrator for a follow-up planning pass on the buffer. Nothing in this phase builds the buffer.
Recommended: **A now, C recorded as deferred** (CONTEXT Deferred Ideas). A removes the defect (bounded latency, counted hangs) at the cost of up to one deadline of latency per hung call before the breaker opens; C removes latency entirely but changes delivery semantics.

Part 2 — the script union (D-05). The locked union is `Ok | Fail | Die | Never | Latch`. Converting all 11 hand-written failing layers (D-06, ROADMAP criterion 3) includes `AuditDecisionSinkLive.test.ts:476`, "an adapter that interrupts itself is a write failure and trips the breaker", whose layer returns `Effect.interrupt`. None of the five modes produces an interruption the adapter raised itself (`Die` is a defect, `Never` waits for the caller). Recommended: **six modes, `Ok | Fail | Die | Interrupt | Never | Latch`, the closed union written out in full** (your closed-union preference). Alternative: keep five and keep that one layer as a reviewed exception, which contradicts ROADMAP criterion 3 and D-07's empty allow-list.

Part 3 — the released options. `failWith`, `failStageWith` and `failCommitWith` shipped in `@qadi/audit@0.11.0` (release commit d0884e6). A script subsumes them (`Fail` is a reply). Recommended: **remove them** — one way to script a double, as core's `scriptedPort` has — and say **Breaking** in the changeset (pre-1.0, so the fixed group's minor). Alternative: keep them as aliases derived from the script (source-compatible, two ways to say one thing).
