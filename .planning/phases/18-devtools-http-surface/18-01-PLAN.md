<objective>
Give the devtools HTTP routes (the decision stream, its JSON backlog and the permission registry) one address rule that a host can prefix, shared with the client that connects to them (SURF-01..SURF-03; ARCH-66).

Purpose: on 1721a42 the three paths are literals in three files (`DecisionStreamRoute.ts:227`, `DecisionBacklogRoute.ts:52`, `PermissionRegistry.ts:166` and `:186`), no constructor takes a prefix, and a client spells the path again by hand (`examples/nextjs-newsroom/src/client/Dock.tsx:67` `url: "/api/__decisions"`, `features/.../decision-log.steps.test.ts:195`). A host that mounts the routes anywhere else breaks its own client silently. Merged ARCH-52 (Phase 7, ADR-QD-107) solved the same problem for port routes with `PortRouteAddress.ts`; this plan follows that shape.

Output: a public, import-free leaf `DevtoolsRouteAddress.ts`, a `prefix` option on every devtools route constructor, the RED-then-green round trip, the overview rows, and (option-b) one mounting call.
