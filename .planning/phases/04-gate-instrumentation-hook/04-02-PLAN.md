Facts the executor needs, verified on 2026-11-08 at commit c3ce9d2:
- After plan 04-01, `GateWriter.ts` exports `useGates<K extends string>(kind, questions): Gates<K>`, where `Gates` is `{ results, entries }`. `useGates` opens the group with the atom set's `decisions` opener, memoised on `[atoms, questions]`. It looks up each entry's decision atom with the `decision` opener, memoised on `[atoms, group]`. Grouped kinds get ids `${useId()}/${name}`. `hooks.ts`'s `useQuestionsAs` (lines 92-136 at HEAD) is still the old body: its own group memo, its own `useId`/`useRef`, its own identities memo calling the `decision` opener, and its own `useGateRegistrations` call.
- **D-03 and the identity rule, as implemented.** No `QadiAtoms` member returns the entry atoms the `decisions` opener reads, and widening `QadiAtoms` would be a breaking change, which D-09's patch changeset rules out. Using the group atom itself as each entry's identity would re-register every sibling whenever one entry changes. That breaks BEH-QD-068's requirement (spec/behaviors/09-react.md:433-441) that a grouped hook "MUST unregister exactly an instance whose name is dropped". So `useQuestionsAs` stops looking up atoms at all (D-03), and the one per-entry lookup lives in `useGates`, memoised on the group so an equal re-render performs none. Task 1 pins that. Record this reasoning in the SUMMARY; plan 04-03 writes it into ADR-QD-111.
- **Counting from a test.** `QadiProvider` takes any `QadiAtoms`. A spread copy `{ ...real, decision: …, decisions: … }` keeps `real.gates` (the same registry object, so its private writer slot is found) and `real.hydrate`. The atom set's own grouped atom calls its closure-local `decision`, not the property, so a spy on the property counts only hook-level lookups. `GateRegistry.test.tsx:618-643` already counts registry notifications through `gates.subscribe` across re-renders.
- `hooks.test.tsx:186-216` already pins that two components asking equal `usePolicies` records get the identical result object. `GateRegistry.test.tsx:548-658` pins one instance per name, nothing uninstrumented, exact unregistration of a dropped key, unregistration on unmount, no re-registration for an equal record rebuilt each render, and a `useQuestions` resource carried through. Every one of them must pass unedited (D-06).
- React's `useId` values contain no `/`. `GateRegistry.test.tsx:580` relies on that by slicing after the first `/`.
