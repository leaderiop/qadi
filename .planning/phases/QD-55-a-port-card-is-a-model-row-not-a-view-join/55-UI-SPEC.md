# Phase QD-55 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This phase changes no pixel and no word.** It is a behaviour-preserving refactor of the devtools
Services tab (`packages/devtools/src/react/ServicesPanel.tsx`, mounted by `DevtoolsDock.tsx`).
CONTEXT.md D-09 and D-13 lock every card's text, `data-testid`, `data-port` and `data-defaulted`
byte-identical to the phase base. Every value below is therefore a *record of what exists*, locked,
and not a proposal. Any change to rendered output is out of scope and conflicts with D-09/D-13.

Source of truth for the values: `ServicesPanel.tsx` and `packages/devtools/src/react/theme.ts` at
the phase base (`4d891643`). The characterisation test (D-13) is the executable form of this document.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | `marginTop` of the calls block and of the uncollected note; border radius of `card` |
| sm | 8px | `gap` between header spans and between call-row cells |
| card gap | 6px | `marginBottom` between cards |
| card padding | 6px 10px | `card` padding (vertical, horizontal) |
| md | 16px | not used on this screen |
| lg | 24px | not used on this screen |

Exceptions: 6px and 10px are existing values, not multiples of 4. They are locked as-is and must not
be normalised by this phase. No touch targets exist on this screen (no interactive element).

## Color

Dark theme only, not themed (`theme.ts`). No colour is added or changed.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colors.surface` `#14161a` | Dock body behind the cards |
| Secondary (30%) | `colors.border` `#2a2f39` | Card outline (`1px solid`); text colour `colors.text` `#e6e8ec` for titles and state |
| Accent (10%) | `colors.accent` `#4ea1ff` | Not used on this screen |
| Warning (amber) | `colors.error` `#e3a008` | Two uses only, below |
| Muted text | `colors.textMuted` `#8b93a3` | Activity line, consequence line (default tone), call interpreter and duration, uncollected note, "and N earlier", scope note, absent note |

Accent reserved for: nothing on this screen (accent is the dock toolbar's active-button colour).

Amber (`colors.error`) is used for exactly two things, and the contract is that it stays two:
1. The consequence line of a card whose `defaulted === true` (the "fail-closed default is a warning,
   not an error" vocabulary rule). In the model this is the row's tone: `warning` when defaulted,
   `plain` otherwise (D-02).
2. The `qadi-wiring-failed` paragraph (layer failed to build).

There is no destructive colour: the screen has no destructive action.

## Layout and Structure (locked)

Order inside `qadi-services` (outer `div`, `diagnosticsRootProps(status)`):

1. `DiagnosticsNotice` (shared, unchanged).
2. The wiring view for the current tag: nothing, the absent note, the failed note, or the cards.
3. The scope paragraph `qadi-activity-scope` (always present, fixed prose, `marginBottom: 0`).

For tag `Read`: one `qadi-port` card per `report.ports` row, in report order (the registry's five
ports, then `EvaluationId`, `CurrentSubject`, `DecisionCache`, `DecisionSink`), then `qadi-cache-card`.

Port card (`section`, `card` style) = header row + consequence + optional calls block:
- Header: `display:flex; gap:8; alignItems:baseline; flexWrap:wrap` holding `<strong>` port name,
  `qadi-port-state` (11px), `qadi-port-activity` (11px, muted).
- Consequence: `qadi-port-consequence`, 11px, muted, amber when defaulted.
- Calls block (below the consequence, `marginTop: 4`): one of three, or nothing (see States).

Call row: `display:flex; gap:8`, 11px: description span, optional `qadi-port-call-interpreter` (muted),
`qadi-port-call-duration` (muted). "and N earlier" is a muted 11px row after the list.

Cache card (`section`, `card` style): header row `gap:8; alignItems:baseline` (no wrap) with
`<strong>DecisionCache</strong>` and `qadi-cache-size` (11px, not muted), then a muted 11px prose
line (no testid).

Interaction: none. The screen is read-only, has no focus targets, no hover or pressed state, no
keyboard behaviour and no motion. This phase adds none.

Rendering split this phase fixes (not a visual change): the model (`PortCards.ts`) supplies every
string, the tone, the `data-port`/`data-defaulted` values, the call-row React key, the tag, and the
calls union; the view maps tag to JSX and prints fields. Fixed prose stays in the view (D-04): the
process-wide scope note, the no-TTL sentence, and the three wiring-note paragraphs with their
`<code>` fragments.

## Copywriting Contract

Every string below is locked byte-identical (D-09). "Model" = supplied by `portCards` after this
phase; "View" = fixed prose remaining in `ServicesPanel.tsx`. No emoji, no punctuation change, no
trailing-space change.

### Fixed prose (View)

| Element | testid | Copy |
|---------|--------|------|
| Wiring absent (tag `NotHanded`, sampled only) | `qadi-wiring-absent` | `No layer was handed to the dock, so which implementation is behind each port cannot be shown. Pass <code>diagnostics={{ layer }}</code>, or a <code>wiring</code> report read elsewhere.` (JSX source line breaks collapse to single spaces; the `{" "}` before `<code>wiring</code>` is one space) |
| Wiring failed (tag `Failed`) | `qadi-wiring-failed` | `The layer handed to the dock failed to build, so which implementation is behind each port cannot be shown: ` followed by the reason (amber) |
| Calls uncollected | `qadi-calls-uncollected` | `What each call asked is not shown — pass <code>portCalls</code> from <code>collectPortCalls</code> to read it from the spans.` (the dash is an em dash) |
| Activity scope | `qadi-activity-scope` | `Call counts are process-wide aggregates — not per request, and not per decision. Correlating a call with one evaluation would mean threading a collector through the evaluator, which risks the short-circuit guarantee for a debug view. The listed calls are read from spans instead, and are the recent ones rather than all of them.` |
| Cache card body | (none) | `Bounded by capacity and evicted by insertion order — there is no time-to-live. Flushing a cache differs from clearing this panel's log.` |
| Cache card title | (none) | `DecisionCache` |

The uncollected note and the absent note do not render in the `NotHanded` + unsampled case
(`wiringView` returns `null`). That suppression is behaviour and stays (see States).

### State words (Model)

| Element | testid | Copy |
|---------|--------|------|
| State, not present and required | `qadi-port-state` | `not provided to this reader` |
| State, not present and not required | `qadi-port-state` | `absent` |
| State, present and defaulted | `qadi-port-state` | `defaulted — {name}` with `name` falling back to `unnamed` (em dash) |
| State, present, not defaulted | `qadi-port-state` | `{name}`, falling back to `wired, unnamed` |
| Cache size, present | `qadi-cache-size` | `{size ?? 0} completed entries` |
| Cache size, absent | `qadi-cache-size` | `absent` |

Order of the state rules is part of the contract: not-present is checked first, then
`defaulted === true` (read from the mark before the name can hide it), then the name.

### Activity line (Model, `qadi-port-activity`)

| Situation | Copy |
|-----------|------|
| No activity entry, no sample taken and `activity.length === 0` | `no activity reading` (`NO_ACTIVITY_READING`) |
| No activity entry otherwise (including every non-port card) | `never called` |
| Entry present | `{calls} call` + `s` unless `calls === 1`, then ` · {translationCalls} from translation` only when non-zero, then ` · {retries} retried` only when non-zero, then ` · {timeouts} timed out` only when non-zero |

The three suffixes appear in that fixed order. Separator is ` · ` (space, middle dot, space).
Non-port cards (`EvaluationId`, `CurrentSubject`, `DecisionCache`, `DecisionSink`) keep reading
`never called` / `no activity reading` (D-09). Rewording them to "not a port" is deferred.

### Consequence line (Model, `qadi-port-consequence`)

- `defaulted === false`: `if defaulted: {consequence}`.
- Otherwise (`true` or `undefined`): the bare `{consequence}`.
- The consequence strings themselves are unchanged: the five in `PORT_READING` (ADR-QD-160) and the
  four non-port ones in `Wiring.ts` (`identifiers correlate a decision with its trace; nothing else
  depends on them`, `supplied per request, so its absence here says nothing about the application`,
  `every evaluation is computed; a hit and a miss would decide identically`, `decisions are made and
  not observed, so this panel has no log to read`).

### Recent calls (Model, `qadi-port-calls`)

| Element | testid | Copy |
|---------|--------|------|
| Call description | `qadi-port-call` (row) | `describeCall(call)` from `PORT_READING`, plus ` · {attempts} attempts` only when `attempts` is defined and greater than 1 |
| Interpreter label, `remote` | `qadi-port-call-interpreter` | `served` |
| Interpreter label, `toPredicate` | `qadi-port-call-interpreter` | `translation` |
| Interpreter label, anything else or unrecorded | (element not rendered) | none |
| Duration, finished | `qadi-port-call-duration` | `{durationMillis.toFixed(1)} ms` |
| Duration, unfinished | `qadi-port-call-duration` | `in flight` (never `0.0 ms`) |
| Overflow | `qadi-port-calls-more` | `and {N} earlier` where `N = calls.length - 5` |

Rules: newest first (reverse of the log's order), at most `SHOWN_PER_PORT = 5` rows, and the
overflow row exists only when more than 5 calls were collected. Row key stays
`${span}-${String(at)}-${description}` (D-12); the description in the key is the full string, suffix
included.

### Contract rows the template asks for

| Element | Copy |
|---------|------|
| Primary CTA | none: the screen is read-only |
| Empty state heading | none |
| Empty state body | A port with nothing reaching it reads `never called` (or `no activity reading` before the first sample); a collected log with no calls for a port renders no calls block at all |
| Error state | `The layer handed to the dock failed to build, so which implementation is behind each port cannot be shown: {reason}` (see Fixed prose) |
| Destructive confirmation | none: no destructive action exists on this screen |

## UI Considerations

Applicable state considerations resolved: 8 covered, 1 backstop, 0 unresolved

The states below are the combinations the D-13 characterisation test must pin on the phase base and
that must read identically after. Copy is in the Copywriting Contract, not restated here.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Services screen with wiring `NotHanded` | ✅ covered | Sampled: renders `qadi-wiring-absent` and the scope note. Unsampled: renders no wiring element at all, only the notice and the scope note |
| error | Services screen with wiring `Failed{reason}` | ✅ covered | Renders `qadi-wiring-failed` in amber with the reason appended; no cards and no cache card; renders regardless of sampled state |
| empty | Port with no activity entry | ✅ covered | `never called`; `no activity reading` when unsampled and the activity list is empty; identical for the four non-port cards |
| zero-one-many | Activity counts (`calls` of 0, 1, many; each suffix zero or non-zero) | ✅ covered | `1 call` vs `N calls`; each of `from translation`, `retried`, `timed out` omitted at zero and shown in fixed order otherwise |
| partial | Calls collection (`portCalls` undefined vs defined, sampled vs not) | ✅ covered | Undefined and sampled: uncollected note. Undefined and unsampled: no calls block. Defined and empty for that port: no calls block. Defined and non-empty: the list |
| overflow | More than 5 collected calls for one port | ✅ covered | Newest 5 shown, `and {N} earlier` row; exactly 5 shows no overflow row; 6 shows `and 1 earlier` |
| partial | Call row fields (attempts, interpreter, duration) | ✅ covered | `· N attempts` only when `attempts > 1`; `served` / `translation` / none; `in flight` vs `x.x ms`; unrecorded span fields read `not recorded` via `PORT_READING` |
| populated | Cache card (`present`, `size` defined or `undefined`, absent) | ✅ covered | `N completed entries` (size `undefined` reads `0 completed entries`) vs `absent` |
| long-text | Long port `name`, reason, resource id or attribute | 🧪 backstop | Text wraps inside the card (`flexWrap: wrap` on the header only; call rows and the consequence do not truncate). No truncation style exists today and none is added; a visual long-string check is the only evidence |

Attribute defaults carried by the cards (also pinned): `data-port` is the row's port name;
`data-defaulted` is `"true"` or `"false"`, and the attribute is absent when `defaulted` is
`undefined` (absent port, or a non-port row).
