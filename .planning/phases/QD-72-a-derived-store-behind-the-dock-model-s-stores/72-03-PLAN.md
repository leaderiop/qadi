## ADR-QD-185 — The dock model's computed stores are derived stores

Rev 1.0, Effective Date 2026-11-22, Status `Accepted — extends ADR-QD-168, amends ADR-QD-047, corrects ADR-QD-169`,
Change History `1.0 (2026-11-22): new — the dock model's three computed stores are derived stores (ARCH-119,
CCR-QD-464)`. Prose, hand-wrapped at about 90 columns as the other ADRs are; no `typescript`/`tsx` fence (a `ts` listing
of the constructor's signature is allowed). Every sentence states the decided mechanism in the present tense; the
code before ADR-QD-185 is named that way where the context needs it.

- **Context.** The dock model computed three stores by hand: the shown reading (the diagnostics store), the questions
  join and the services view. Each kept its own last key in a `let`, compared it field by field in hand-written code,
  and subscribed itself to its parents; the questions and services stores also checked a closed flag the shown reading
  did not, so a closed model still merged a later reading into the diagnostics store. A key field added to the compute's
  input and missed by the hand compare would leave a store stale with nothing failing. The store count was stated in
  five places (ADR-QD-047's amendments, ADR-QD-162, ADR-QD-168, BEH-QD-465 and the `DockModel.ts` header).
- **Decision**, numbered:
  1. One scoped constructor in `ExternalStore.ts`: `makeDerivedStore({ parents, key, compute })`, an
     `Effect.fn("qadi.devtools.makeDerivedStore")` returning `Effect<DerivedStore<A>, never, Scope.Scope>`. `parents`
     is a non-empty tuple of `Parent` (anything with `ExternalStore`'s `subscribe`); `key` is a thunk read on every
     trigger, because a key may read the model's own inputs, which `configure` assigns before the feeds publish (one
     `configure` publishes one join); `compute` runs once at construction without notifying. `DerivedStore<A>` is the
     read half plus `refresh()`, the trigger for a key input that is not a parent.
  2. Key equality is per-field identity over the union of both keys' own enumerable fields, by one module-private
     comparison, `sameFields`; a field on one side only is a change; values compare with `===`, as `set` does.
  3. What enforces what: the compiler refuses a key type with an optional field (`K extends object & Required<K>`), an
     empty parent list, and a compute reading a field outside its key; a key reader typed with the compute's input
     type is refused when it misses a field. A test pins per-field recompute and keys of other shapes. Neither
     enforces that a compute reads only its key; the dock's three computes are module-scope functions of their key.
  4. The read half has one name, `ReadableStore<A>`, used at every site that spelled it as a `Pick`.
  5. On a trigger with an unchanged key nothing runs; otherwise it computes, then commits the key, then `set`s: a
     throwing compute commits nothing and the next trigger recomputes; a change notifies once, or not at all when the
     compute returns the held reference; a refresh from inside its own listener sees the committed key.
  6. ADR-QD-177 holds unchanged for its listeners (pointed at, not restated). Its refresh is a listener in each parent,
     subscribed in the listed order at construction, so it moves before every listener added after it, and a throw
     from its listeners enters the parent's loop as one value.
  7. A finalizer in the caller's scope releases every parent and stops it: no key read, no compute, `refresh` does
     nothing, the last snapshot is kept, and `subscribe` registers but nothing notifies. The same for all three stores,
     so a closed model's diagnostics store no longer merges a later reading: closing the scope ends what the model
     started (ADR-QD-137), and `DiagnosticsFeed`'s `configure` already refuses a closed feed. The dock never hands a
     closed model, so nothing it shows changes.
  8. Package-private: `ExternalStore.ts` stays out of the barrel (ADR-QD-099); the root export count and
     `spec/overview.md` do not change. The timeline fan-out is not a computed store (it pushes a command into the
     explorer, the simulation and the dock session) and `sightings` is a thunk, so neither moves onto it.
  9. The dock model: `shownReading` (parents the diagnostics feed; key the feed's snapshot and the supplied reading;
     compute the module-scope `mergedOf`), `questions` (parents the gates feed and `shownReading`; key `JoinKey`) and
     `services` (parent `shownReading`; key `ServicesInput`; compute `portCards`), built in that order; `configure`
     refreshes `shownReading` where it re-merged by hand. `DockModel.ts` holds no last key and no closed state.
  10. The store count is stated once, in BEH-QD-700, as the list of `DockModel` members with `subscribe` and
      `getSnapshot`, and a test of a built model checks that exact list. ADR-QD-047 and BEH-QD-465 get one dated
      amendment each pointing at it; ADR-QD-162, ADR-QD-168 and ADR-QD-169 get dated notes; history is kept as
      written (AGENTS.md §15).
  11. As ADR-QD-168 noted for the port cards, the model and not a panel `useMemo` is where a computed view lives.
- **Alternatives considered**, each with why: `Data.struct` keys with `Equal.equals` (structural in effect v4: deep
  compares the guard arrays and policies every tick, and turns an identity rule into a structural one); a record of
  per-field readers (its result type needs a cast); a key schema (a codec with no trust boundary, AGENTS.md §7); key
  inputs held in stores `configure` sets last (the join would publish twice per `configure`); one derived store per
  feed (the questions join reads two parents); making it public (freezes an internal mechanism); leaving the shown
  reading unguarded after close (two rules for three stores).
- **Consequences**: the derived store's rules are tested once against `makeDerivedStore`, and the dock's tests keep
  one test per store; `DockModel.ts` has no hand compare left to miss a field; a closed model's diagnostics store stays
  as it was (no changeset: unreachable through `DevtoolsDock`); the count is a test failure, not a sentence to keep in
  step; ADR-QD-169's consequence that the model keeps its closed flag and last join is corrected.
- **Related**: links to ADR-QD-047, ADR-QD-099, ADR-QD-137, ADR-QD-162, ADR-QD-168, ADR-QD-169 and ADR-QD-177; to
  BEH-QD-696 to BEH-QD-700 (`../behaviors/28-devtools-screens.md#…`) and INV-QD-389 and INV-QD-390
  (`../invariants.md#…`), with the anchors of the interfaces.
