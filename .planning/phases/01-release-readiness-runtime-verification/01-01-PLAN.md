<objective>

declared `"engines": {"node": ">=20.19.0"}` since CCR-QD-036 while CI has only

it. This plan makes the merge gate itself the enforcement, then closes the four
places in the repository that still describe the floor as unverified.

Output: `.github/workflows/check.yml` running the identical `pnpm check` suite
on both Node 20.19.0 and Node 26, plus the doc-claim corrections D-08 requires.
</objective>

The deterministic edge-probe engine classified COMPAT-01's row as
`unclassified` and could not propose a predicate for it. That row stays
unresolved by design — the spec-less fallback rules forbid auto-resolving an
`unclassified` row with a backstop marker, and forbid dropping it silently.

Why the engine could not classify it: its taxonomy (adjacency, empty input,
ordering) is aimed at collection-processing code, and COMPAT-01 is an assertion
about a CI job's runtime, which has no collection, no elements and no ordering
to probe. Rather than force it into that shape, the four `must_haves.truths`

contents, matrix-expression wiring, timeout budget, and an observed green run
on both legs.

The residual risk this leaves, stated plainly: nothing in this plan proves that
Node 20.19.0 *stays* the floor. If a future dependency bump raises a transitive
`engines` requirement above 20.19.0, the floor leg will start failing, and the
prohibition above is what should be re-read at that point rather than the
easiest fix taken.
