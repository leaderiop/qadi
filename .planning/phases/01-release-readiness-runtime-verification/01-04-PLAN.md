in this repository are substantial and explain why, not only what. The seams

Apply judgment; the specific list of what to fix is explicitly Claude's
discretion per D-13. The seams worth looking at:

  - **Ordering within a heading.** Entries land in whatever order the tool
    emitted them, which carries no meaning. Where one entry in a section
    changes an API and another does not, put the API change first — a reader
    scanning a release for "what breaks my build" should not have to read past
    a verification-hardening note to find it. This matters concretely in
    `packages/audit/CHANGELOG.md`, whose two entries are exactly that pair: the
    ADR-QD-057 signature entry is the API change and must come first, ahead of
    the INV-QD-051 invariants entry.
  - **Repetition across entries.** Several `@qadi/core` changesets were written
    months apart and each re-establishes context the previous one already gave.
    Read as a single document they repeat. Trim the restatement, keep the fact.
  - **Cross-references that no longer resolve.** A changeset body written as a
    standalone note may say "see the changeset above" or refer to a sibling
    package's change that landed in a different section. Make those read
    correctly in their new home.
  - **Dependency-bump noise.** `updateInternalDependencies: "patch"` generates
    `Updated dependencies` blocks. Leave them; they are accurate and a reader
    skips them. Do not delete them to make the file shorter.

| Boundary | Description |
