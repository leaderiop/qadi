<objective>
Close UAT gap G-01-1: a genuine TOCTOU race in `@qadi/react`'s suspense promise
that makes the `check (20.19.0)` merge-gate leg fail reproducibly, blocking
COMPAT-01.

`settled()` in `packages/react/src/hooks.ts` subscribes to a decision atom
without ever reading its current value. `AtomRegistry.subscribe` notifies on
*transitions* only — verified in `effect@4.0.0-rc.110`'s source — so a
subscription registered after the atom has already reached its terminal state
receives nothing, and the promise hangs forever. On Node 20.x an extra stale
render of an already-suspended component (observed only when preceded in the
same file by a test that drives an `Effect.fail` resolver to completion) calls
`settled()` a second time against that already-settled atom, and the Suspense
boundary never clears.

This is the incompatibility D-07 anticipated: *"If Node 20.19 reveals a real
incompatibility (not just 'previously untested but fine'), fix it within this
phase rather than lowering the floor or deferring."* The floor stays at
20.19.0 and stays blocking (D-06); the library gets fixed.

Plans 01-01 through 01-04 are all executed and their work stands — this plan
adds nothing to and removes nothing from the Node matrix, the changesets, the
fixed group, or the 0.3.0 changelogs. It fixes one library defect that the
matrix D-05 added is what first exposed.

Purpose: turn the declared engine floor into a passing gate, and make the

    - `isPending` — takes a `DecisionResult`, returns `true` when the result is

      `useDecisionSuspense`'s throw condition read it, so the two cannot
      drift apart again. `waiting` counts as pending deliberately: a decision
      being re-checked is not a decision (ADR-QD-017), and resolving on one
      would surface the *previous* verdict through the Suspense path.
    - `settled` — same signature as the current private helper: takes the
      `AtomRegistry` and the decision `Atom`, returns `Promise<void>`.

    `settled`'s body, in this exact order, because the order is the fix:

    1. Return the memoised promise for this atom if there is one. Keep the
       module-private `WeakMap` keyed by atom that `hooks.ts` holds today,
       and keep its existing rationale: React re-renders on every throw, so a
       distinct promise per throw would suspend forever.
    2. Read the atom's current value with `registry.get(atom)`. If `isPending`
       is false for it, the decision is already known — return
       `Promise.resolve()` and do not touch the `WeakMap`. This is the branch
       that closes the gap: today no such branch exists, so an
       already-terminal atom is subscribed to and waited on forever.
    3. Otherwise subscribe exactly as today — on a callback whose result is
       not `isPending`, unsubscribe, delete the `WeakMap` entry, resolve —
       then store the promise in the `WeakMap` and return it.

    Two constraints on that shape that are not obvious and must be honored:

    - Steps 2 and 3 are one uninterrupted synchronous block. Nothing can
      interleave between the read and the subscribe, which is precisely why
      the read is sufficient and no window remains.
    - Do NOT instead pass `{ immediate: true }` to `registry.subscribe`. Two
      concrete problems, both verified against `effect@4.0.0-rc.110`'s
      `AtomRegistry.ts`: that option invokes the callback *before* `subscribe`
      returns, so the callback runs while the unsubscribe handle is still in
      its temporal dead zone; and because the promise executor runs
      synchronously, the callback's `WeakMap` delete would run before the
      `WeakMap` set on the following line, permanently caching a
      already-resolved promise for that atom — which would then be handed back
      after `useInvalidate` sends the decision back to pending, and the
      boundary would never re-suspend. Reading first has neither problem.

    - Delete the local helper, the `WeakMap`, and their doc comments (they
