## Planning-time findings (probed on `dd071c7c` in a throwaway test, deleted; `git status` clean afterwards)

- **A sink whose `record` throws before it returns an effect is not contained on the base.** `{ record: () => { throw … } }`
  through `evaluate` exits `Cause([Die(Error: sync)])`: `emit(record)` evaluates `sink.value.record(record)` eagerly,
  outside `catchCause`. That breaks INV-QD-035 and is a cause D-03 says the emitter reports ("a throw"); row E5 pins it,
  RED on the base for the decision, and 46-03 suspends the call.
- **A `catchCause` handler that throws synchronously ends the effect with a defect** (`Cause([Die(Error: handler
  threw)])`); the same body inside `Effect.suspend` and an inner `catchCause` succeeds. So the report must be built lazily
  and contained (D-04), and a sink's `name` is read inside that containment, never when the emitter is built (a throwing
  getter there would die in `evaluate`). Decided: a `name` getter that throws is reported once as `unnamed` (E7, RED on
  the base, which reads no name and reports nothing).
- **A self-interrupting sink already leaves the decision unchanged on the base** (RESEARCH A1); only its count is RED (E3,
  O3).
- **A sink that never reads its `name`** (a shape with a throwing getter, handed to `Layer.succeed`) builds and evaluates
  to `Allow` on the base: the layer does not read the field.
