<objective>
Give ledger adapters a way to prove the one obligation 11-03 left them: `entriesAt(key)` answers exactly the entries
appended under `key`, byte for byte. The keyed interface makes the loose read idioms unwritable in the adapter's
signature, but a type cannot rule out a store whose collation folds case, trims trailing spaces or normalises Unicode;
the suite appends a fixed table of adversarial pairs and reads each back. `checkSignatureHistoryScoping` checks the same
rule for a deployment whose e-signature system is its `SignatureHistory` (no ledger).

Ported from lost commit `8900b7e` (`SignatureLedgerConformance.ts`, its test, the BDD scenario, the audit docs). Every
lost id in ported text is rewritten (D-06): the lost "ADR-QD-110" becomes ADR-QD-117, "BEH-QD-336" becomes BEH-QD-339,
"ARCH-52" becomes ARCH-59. Spec records themselves are 11-06.
</objective>
