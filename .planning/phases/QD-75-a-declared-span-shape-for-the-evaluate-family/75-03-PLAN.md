## The module (this plan's part)

`packages/core/src/EvaluationSpan.ts`, package-private (no barrel line), imports `effect/Effect`, `effect/Schema`,
`type { Decision }` from `./Decision.ts`, `{ POLICY_TAGS }` from `./Policy.ts`, the span types from `./PortSpan.ts`, and
`spanStruct`, `encodeSpan`, `sharedQuestionFields`, `sharedQuestionKeys` from `./PortSpanEncode.ts`.

- Header doc comment: one-line summary "The spans of the evaluate family, each declared once: its name, the question
  annotated before the work, and the answer annotated after it." Then the why, written so it needs no change when
  75-04 adds spans: each key is spelled once, in this file, and `qadi.subject_id` is the port spans' own
  (`sharedQuestionKeys`); a writer annotates through `annotateSpan`, so the question and the answer are written from
  the declaration and a failed span still carries its question (ADR-QD-188, extending ADR-QD-051 and ADR-QD-109);
  every field is a `SpanValue` leaf by type (INV-QD-044); out of the barrel (AGENTS.md §9) because a host has no span
  of this family to write. What enforces it, honestly: the compiler (field types, the outcome tie, `name` typed
  `SpanKey`) and `EvaluationSpan.contract.test.ts` (the keys a tracer receives). Name nothing that does not exist yet.
- `export type SpanOutcome = Decision["_tag"] | "Failed";` with a doc line saying a failure is not a decision, so it is
  the third value.
- A module-private typed identity `declareSpan`, generic over `const Q extends SpanFields` and `const A extends
  SpanFields`, taking `{ readonly name: SpanKey; readonly question: SpanStruct<Q>; readonly answer: SpanStruct<A> }`
  and returning it, so `name` is typed `SpanKey` with no cast (the `portSpan` pattern in `PortSpanEncode.ts`).
- Module-private shared pieces, each key literal once: `askedFields` (`subjectId: sharedQuestionFields.subjectId`,
  `policyTag: Schema.optionalKey(Schema.Literals(POLICY_TAGS))`, `action: Schema.optionalKey(Schema.String)`) and
  `askedKeys` (`subjectId: sharedQuestionKeys.subjectId`, `policyTag: "qadi.policy_tag"`, `action: "qadi.action"`, `as const`, because a widened `string` is not a `SpanKey`);
  `failedFields` (`errorTag: Schema.optionalKey(Schema.String)`) and `failedKeys` (`errorTag: "qadi.error_tag"`, `as const`); the
  outcome list `["Allow", "Deny", "Failed"] as const satisfies ReadonlyArray<SpanOutcome>`.
- `export const evaluateSpan = declareSpan({ name: "qadi.evaluate", question: spanStruct({ ...askedFields,
  evaluationId }, { ...askedKeys, evaluationId: "qadi.evaluation_id" }), answer: spanStruct({ outcome:
  Schema.optionalKey(Schema.Literals(outcomes)), ...failedFields, obligations: Schema.optionalKey(Schema.String) }, {
  outcome: "qadi.outcome", ...failedKeys, obligations: "qadi.obligations" }) })`, each declaration with a doc comment
  stating what it answers (the outcome on every path; the error tag only on `Failed`; the obligations comma-joined
  only on an allow that owes some).
- `export const denialEvent = spanStruct({ policyTag: askedFields.policyTag, subjectId: askedFields.subjectId,
  reason: Schema.optionalKey(Schema.String) }, { policyTag: askedKeys.policyTag, subjectId: askedKeys.subjectId,
  reason: "qadi.reason" })`, doc comment: the annotations of the denial log line; the reason stays on the log line and
  is never copied to a span.
- `export const annotateSpan = <F extends SpanFields>(struct: SpanStruct<F>, value: SpanType<SpanStruct<F>>):
  Effect.Effect<void> => Effect.annotateCurrentSpan(encodeSpan(struct, value))`, a plain function (not `Effect.fn`:
  it opens no span), doc comment: annotates the current span with one struct of the family.

Each `"qadi.<key>"` literal appears once in the file, on a key line; the span name appears on its `name:` line; no
comment spells a key.
