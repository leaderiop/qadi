<objective>
Make the request key injective and total (D-02, D-03; KEY-01, KEY-02, KEY-03): `PortKey.ts`'s `canonicalKey` becomes a kind-tagged, stack-safe encoding that agrees with `Equal.equals` on a stated domain and returns a typed refusal outside it; all five port descriptions derive their key from it; and the refusal vocabulary is public. Handling the `Result` at every consumer is plan 17-04 (split out so each plan stays small and the consumer inventory is re-derived against the post-Phase-11 tree).

Purpose: two port requests that the evaluator tells apart (`Equal`) must never share a captured or scripted answer, and a request the key cannot represent must fail loudly and closed instead of colliding or overflowing the stack. The library then has one definition of request identity (`Question` and `DecisionCache` already use `Equal.equals`).

Output: a rewritten `PortKey.ts`, a `Result`-typed `PortDescription.key` with its refusal vocabulary, five one-expression key changes, the key's own tests, and three overview rows.
</objective>

Planning-time facts (HEAD 1721a42; Phase 13 may shift line numbers, so find code by name):

The domain and its agreement with `Equal.equals` (`effect@4.1.2`, measured; see 17-02's `<interfaces>` for the probe table). This is the decision D-02 asked the planner to make and document:
- Plain objects and arrays: `Equal.equals` IS structural, so the key law's right-hand side stays `Equal.equals` (no ADR-094 rewording to "structurally equal" is needed; KEY-05 names `Equal.equals` restricted to the domain).
- `-0` and `0`: equal under `Equal`, so they key alike (`String(-0)` is `"0"`).
- `NaN`: equal to itself under `Equal`, so it keys as itself, distinct from `null` and from ±Infinity. Two invalid Dates are equal, so an invalid Date keys by `NaN` time.
- Object keys: `Equal` reads every own key, symbol and non-enumerable included. The key reads every own string key, non-enumerable included (`Object.getOwnPropertyNames`), and refuses a symbol key.
- Arrays: `Equal` compares indices only (an extra own property is ignored; a hole equals `undefined`). The key does the same.
- Class instances: `Equal` compares them structurally over own **and prototype** keys, which makes `new Number(1)` equal `new Number(2)` and `new Uint8Array([1])` equal `new Int8Array([1])`. No text key can reproduce that soundly, so everything whose prototype is not `Object.prototype`, `null`, `Array.prototype`, `Date.prototype`, `RegExp.prototype`, `Set.prototype` or `Map.prototype` is refused as `Unkeyable` kind `instance` (with the constructor's name as `brand`, as `JsonHazard.ts`'s `brandOf` reads it). That covers boxed primitives, binary data, `Error`, `Promise`, `WeakMap`/`WeakSet` and Effect data types implementing `Equal`.
- Functions and symbols: `Equal` compares them by identity, which text cannot carry; refused as `Unkeyable` kind `function` / `symbol`.
- Cycles: `Equal` is coinductive (two isomorphic cycles are equal); the key refuses with `Circular { path }`. A shared, acyclic reference (the same object twice) is fine and is encoded twice.
- A getter or proxy trap that throws while being read: `Unreadable { path, message }`.

Encoding format (Claude's discretion per CONTEXT; fixed here so the executor does not re-derive it). Every value becomes one self-delimiting token, so a sequence of tokens joined by `,` is unambiguous:
- `undefined` → `u`; `null` → `n`; `true` → `t`; `false` → `f`
- number → `d` + (`NaN` for NaN, otherwise `String(x)`, which already writes -0 as `0`) + `;`
- bigint → `b` + decimal digits (with sign) + `;`
- string → `s` + `JSON.stringify(x)`
- Date → `D` + (`getTime()`, `NaN` when invalid) + `;`
- RegExp → `R` + `JSON.stringify(String(x))`
- array → `[` + the tokens of indices `0 … length-1` (a hole reads as `undefined`) joined by `,` + `]`
- plain or null-prototype object → `{` + one `JSON.stringify(key) + ":" + token` per own string key, sorted by that text, joined by `,` + `}`
- Set → `S{` + member tokens sorted, joined by `,` + `}`
- Map → `M{` + one `keyToken + "=" + valueToken` per entry, sorted, joined by `,` + `}`
Sorting is by UTF-16 code unit (`toSorted()` with no comparator), so a Set or Map of Equal-duplicate members (two distinct `{ a: 1 }` objects) keys as the multiset `Equal`'s one-to-one matching compares.

Stack safety: the walk keeps an explicit work stack of frames (no recursion), assembling each container's token after its children, in the style of `JsonHazard.ts`'s `wireHazard` (an `onPath` set for cycle detection, a `pathHere()` for the refusal path). No depth limit is imposed; a 100,000-deep array encodes.

Refusal vocabulary, declared in `PortDescription.ts` beside `key` (public through the barrel's existing `export * from "./PortDescription.ts"`, so `@qadi/devtools` and `@qadi/audit` can import it from `@qadi/core`):
- `UnkeyableKind = "function" | "symbol" | "symbol-key" | "instance"` (written in full).
- `KeyRefusal = Data.TaggedEnum<{ Circular: { readonly path: WirePath }; Unkeyable: { readonly path: WirePath; readonly kind: UnkeyableKind; readonly brand: string }; Unreadable: { readonly path: WirePath; readonly message: string } }>` with its `Data.taggedEnum` constructor, mirroring `JsonRefusal.ts`'s `EncodeRefusal`. `WirePath` is imported as a type from `JsonRefusal.ts`: the package's one type for "where inside a value".
- `describeKeyRefusal: (self: KeyRefusal) => string`, a module-scope `Match.type<KeyRefusal>().pipe(Match.tagsExhaustive({…}))`, naming the path the way `JsonRefusal.ts`'s `where` does.
- `PortDescription.key: (args: Args) => Result.Result<string, KeyRefusal>`. Precedent: `PortWire`'s encode and decode already return `Result`, "never a throw" (`spec/overview.md`, `PortWire` row).

Current key expressions, each replaced by `canonicalKey([…])` over the same fields in the same order (absent and `undefined` fields key alike, because they are tuple elements, not object keys):
